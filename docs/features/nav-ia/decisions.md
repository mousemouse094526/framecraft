# Decisions: nav-ia

## D1: ที่อยู่ของทุกหน้าขึ้นต้นด้วย hash ของหัวข้อหรือคลังที่มันอยู่ในเมนู

**Chosen:** ทุก route อยู่ใต้ hash ของรายการเมนูที่มันเป็นของ: ของสปอยอยู่ใต้ `#/spoil`, ของ reel cover ใต้ `#/covers`, คลังแต่ละอันมี hash ระดับบนของตัวเอง. ย้ายของในเมนูต้องย้าย route ด้วย ไม่ย้ายแค่ป้าย.

**Why:** เจ้าของบอกว่า "route และ menu ต่างดูแปลกๆมาก ... menu ไหนควรอยู่อันไหน"; `tabOf()` เลือกหัวข้อจาก prefix ของ hash อยู่แล้ว ป้ายที่ย้ายโดยไม่ย้าย route จึงหลุด (เช่น เสียงที่บันทึกอยู่หมวดคลังแต่ `#/spoil/voices` ทำให้หัวข้อสปอยสว่าง).

**Rejected:**
- ย้ายแค่ป้ายในเมนู route เดิม (แบบ ui-nav D6) — ชื่อกับที่อยู่ไม่ตรงกันต่อไป ซึ่งคือปัญหาที่เจ้าของบอก
- ใช้ router library — แอปใช้ hash ธรรมดามาตลอด (spoil D10) การย้าย route ทำได้ด้วยตาราง `MOVED` ที่มีอยู่

**Details:**
- changes ui-nav D6: hash เปลี่ยนได้ แต่ hash เก่าทุกตัวต้องพาไปหน้าใหม่ (D9)
- ADR-0062 ส่วนที่ว่าเมนูหารายการที่เปิดอยู่จาก hash ด้วยต้นไม้ `NAV_SECTIONS` ที่เดียวยังถือ; ส่วนที่ว่า hash "ไม่เปลี่ยนชื่อหรือหายไป" ถูกแก้ด้วย ADR ของ D1/D9

**From:** interview · **Status:** active

## D2: วัตถุดิบที่หัวข้อเดียวใช้ทำงานต่ออยู่ใต้หัวข้อนั้น; คลังคือของอ้างอิงที่หยิบไปใช้

**Chosen:** คลังคลิปย้ายไปใต้หัวข้อสปอยเป็นรายการ "คลิปทั้งหมด" ที่ `#/spoil/clips`. หมวดคลังเหลือของที่หยิบไปใช้ตอนทำ reel: คลังความรู้ คลังเสียง เสียงพากย์.

**Why:** หน้าคลิปเป็นที่ทำงาน (โหลด ตัด ถอด บรรยาย) ของสปอยอย่างเดียว อยู่หมวดคลังทำให้หาที่ทำงานไม่เจอ; เพลงของ reel cover ก็อยู่ใต้หัวข้อของมันอยู่แล้ว กฎเดียวจึงอธิบายได้ทั้งสองอย่าง.

**Rejected:**
- คงคลังคลิปในหมวดคลัง (ADR-0063 เดิม) — เป็นของที่ต้องทำงานต่อก่อนได้ reel ไม่ใช่ของอ้างอิง และไม่มีหัวข้ออื่นใช้

**Details:**
- changes ui-nav D2 (คลังคลิปไม่อยู่ในหมวดคลัง); supersedes ADR-0063 ด้วย ADR ใหม่ที่บอกกฎของ D2
- ทดสอบกฎ: ของที่หัวข้อเดียวใช้ และผู้ใช้ทำงานต่อก่อนจะได้ reel = วัตถุดิบ; ของที่ใช้ร่วม หรือเขียนไว้แล้วหยิบไปใช้ = คลัง
- ชื่อหน้าในหัวหน้าคือ "สปอย / คลิปทั้งหมด"

**From:** interview (auto mode: Recommended) · **Status:** active

## D3: คลังความรู้คงในหมวดคลัง "ใช้กับ สปอย" ถูกต้องแล้ว

**Chosen:** คลังความรู้อยู่ที่ `#/stories` ในหมวดคลังเหมือนเดิม และบรรทัด "ใช้กับ สปอย" คงไว้.

**Why:** โค้ดยืนยันว่ามีแต่สปอยที่อ่าน Story (`StoryPicker`, `useClipStory` ของ spoil-maker); การ์ตูนเล่าไม่อ่าน. Story เป็นของที่เขียนไว้แล้วหยิบไปใช้ จึงเป็นคลังตาม D2.

**Rejected:**
- เปลี่ยนเป็น "ใช้กับ การ์ตูนเล่า" ตามที่ brief เดา — ไม่ตรงกับโค้ด

**From:** code · **Status:** active

## D4: เสียงพากย์มีที่อยู่ของตัวเอง `#/voices` ในหมวดคลัง

**Chosen:** Saved voice ย้ายจาก `#/spoil/voices` ไป `#/voices`, ป้ายเมนู "เสียงพากย์" (ชื่อที่ `feat/ui-nav-3` ใช้), หัวข้อ `voices` ของตัวเอง. หน้าไม่มีปุ่มกลับไปสปอยอีก เหมือนคลังความรู้.

**Why:** สปอยกับการ์ตูนเล่าใช้ร่วม (toon D8) แต่ route อยู่ใต้ `/spoil/` ทำให้เปิดแล้วหัวข้อสปอยสว่าง (D1). ปุ่มกลับที่ชี้ `#/spoil` เสมอผิดเมื่อมาจากฟอร์มชุดของการ์ตูนเล่า.

**Rejected:**
- ปุ่มกลับแบบ `?back=` อย่างคลังเสียง — ได้ไม่คุ้ม: เมนูกับปุ่ม back ของเบราว์เซอร์พากลับได้ใน 1 คลิก
- คงปุ่มกลับไป `#/spoil` — ผิดครึ่งหนึ่งของทางเข้า

**From:** interview · **Status:** active

## D5: สปอยเป็นพื้นที่ทำงานเดียวที่ `#/spoil`; ขั้นเป็นสถานะในหน้า ไม่ใช่ route

**Chosen:** `#/spoil` เปิดพื้นที่ทำงานสปอย: แถบขั้น เลือกคลิป · ตรวจแก้บท · ผล render เป็นปุ่มในหน้า (กดข้ามขั้นได้) ไม่ใช่ลิงก์ hash. เมนูของสปอยเหลือ "ทำสปอย" กับ "คลิปทั้งหมด" (D2). ที่เคยเปลี่ยน hash ไปขั้นอื่น (ร่างบทเริ่ม, render เสร็จ, ยกเลิกร่าง, ปุ่ม "ไปที่ตรวจแก้บท"/"ไปที่ตั้งค่าคลิปสปอย") เปลี่ยนขั้นในหน้าแทน.

**Why:** เจ้าของบอกว่า "การทำงานแต่ละ menu ก็มีความแปลก ... ต้องเข้าหลายขั้น"; ของจริงคืองานชิ้นเดียว (Spoil draft มีได้ชิ้นเดียว) แต่เมนูทำตัวเป็นตัวบอกขั้น 3 รายการ.

**Rejected:**
- หน้ายาวหน้าเดียวเรียงทั้งสามส่วน — ตรวจแก้บทยาวหลายสิบการ์ด ผล render จะตกไปท้ายหน้าไกล
- คง 3 route แต่ซ่อนจากเมนู — ยังเป็น 3 หน้าต่อกัน และ brief ห้าม route แยกต่อขั้น

**Details:**
- เปิดหน้า: เมื่ออ่านสถานะครั้งแรกเสร็จ มี Spoil draft หรือกำลังร่างบท → ตรวจแก้บท, ไม่มี → เลือกคลิป; อ่านไม่ได้ → เลือกคลิป
- ขั้นที่เลือกไม่ลง history: back ของเบราว์เซอร์ออกจากสปอยไปหน้าก่อน
- แถบขั้นยังบอกสถานะและ spinner ของแต่ละขั้นเหมือนเดิม (spoil-maker D68)
- supersedes ui-nav D3 ส่วนขั้นของสปอยในเมนู; changes spoil-maker D53 (ขั้นไม่มี hash ของตัวเอง)

**From:** interview (auto mode: Recommended) · **Status:** active

## D6: หัวข้อ "แกะเพลง" เป็น "reel cover" ที่ `#/covers`; เพลงหนึ่งเพลงเป็นหน้าเดียวที่มีทั้งแกะโน้ตและ reel

**Chosen:** หัวข้อในหมวดดนตรีชื่อ "reel cover" รายการ "เพลงทั้งหมด" ที่ `#/covers`. `#/covers/{id}` คือหน้าเดียวของเพลง: ช่วงแกะ แกะโน้ต แล้วส่วน reel (เครื่องดนตรี ช่วง ข้อความ เสียง ฟัง render ผล render) ต่อลงมาในหน้าเดียวกัน แทนหน้า `#/songs/{id}/cover` ที่แยก.

**Why:** แกะโน้ตมีไว้ทำ reel cover อย่างเดียวตั้งแต่ไม่มีบทเรียน (reels-only D6); การแยกหน้าบังคับเดิน เพลง → การ์ด Reel cover → หน้า reel เพิ่ม 1 คลิกและ reel ซ่อนอยู่ใต้ชื่อ "แกะเพลง".

**Rejected:**
- คง `#/songs` แล้วเปลี่ยนแค่ป้าย — ชื่อกับที่อยู่ไม่ตรงกัน (D1)
- แยกหัวข้อ "แกะเพลง" กับ "reel cover" สองหัวข้อ — reel cover เป็นของเพลง (ADR-0052) จะได้รายการเพลงซ้ำสองที่

**Details:**
- supersedes drum-cover D11 (หน้า reel แยกที่ `App` เลือก); changes drum-notes D2 (ชื่อหัวข้อและ hash)
- API ยังเป็น `/api/songs/...` ไม่แตะ backend (D13)
- ส่วน reel ขึ้นเมื่อเพลงมีผลแกะแล้ว ก่อนนั้นเห็นแค่ช่วงแกะกับปุ่มแกะโน้ต; ข้อความ "ยังไม่มีโน้ตคาลิมบา" ที่เคยลิงก์ไปหน้าเพลงชี้ไปส่วนแกะในหน้าเดียวกัน

**From:** interview (auto mode: Recommended) · **Status:** active

## D7: reel กลองหนึ่งชิ้นเป็นหน้าเดียวที่ `#/drums/{id}` มีผล render อยู่ใต้ฟอร์ม

**Chosen:** ผล render ของ reel กลองย้ายจาก `#/drums/{id}/renders` ไปเป็นส่วนท้ายของหน้าแก้ reel; render ที่หน้านี้เริ่มแล้วเสร็จ อ่านผลใหม่และเลื่อนไปที่ผลล่าสุด แทนการเปลี่ยน hash.

**Why:** ทำตามรูปเดียวกับหน้า reel cover ที่มีผล render อยู่ในหน้าอยู่แล้ว (drum-cover D7) และตัดหน้าที่บังคับเดิน แก้ → ผล render (D5 Why).

**Rejected:**
- คงหน้า `/renders` แยก — ไม่ตรงกับ reel cover และเพิ่ม 1 คลิก

**From:** interview · **Status:** active

## D8: EP การ์ตูนเล่าเป็นหน้าเดียวที่ `#/toon/eps/{id}`: พล็อต · เส้นเรื่อง · render เป็นสถานะในหน้า

**Chosen:** `/plot` และ `/render` ของ EP ไม่มีอีก: หน้า EP มีปุ่มสลับ พล็อต · เส้นเรื่อง · render ในหน้า; ชุด → EP ยังเป็นหน้าตามข้อมูล (หนึ่งชุดหลาย EP) และหน้าตัวละคร ตั้งค่า เลือกภาพอ้างอิงของชุดคงเดิม.

**Why:** กฎเดียวกับ D5: งานหนึ่งชิ้น (EP หนึ่งตอน) เป็นพื้นที่เดียว ขั้นเป็นสถานะในหน้า; ชุดกับ EP ไม่ใช่ขั้นบังคับแต่เป็นการเลือกของ.

**Rejected:**
- ไม่แตะการ์ตูนเล่า — ทิ้ง 3 route ต่อ EP ไว้ ขัดกับข้อ 2 ของ brief
- รวมหน้าชุดกับหน้า EP — ชุดหนึ่งมีหลาย EP การเลือก EP เป็นการเลือกของจริง

**Details:**
- เปิดหน้า: EP ที่ยังเป็นพล็อต → พล็อต, มีการ์ดแล้ว → เส้นเรื่อง (เหมือน `showPlot` วันนี้); ปุ่ม render ขึ้นเมื่อมีการ์ด
- แตกการ์ดเสร็จ (เดิม `useEp` ตั้ง hash) → สลับเป็นเส้นเรื่อง
- changes toon D53 (hash `/plot`) และ route `/render` ใน toon spec › Frontend

**From:** interview · **Status:** active

## D9: hash เก่าทุกตัวพาไปหน้าใหม่ด้วย `MOVED` แบบ pattern; ล่าสุดที่เก็บไว้ย้ายตาม

**Chosen:** `MOVED` ใน `useHash` เป็นรายการ pattern → hash ใหม่ (รองรับ `{id}`) ใช้ `replaceState` เหมือนเดิม: ตารางใน spec › Implementation › Redirect. "ล่าสุด" ที่เก็บเป็น `#/songs/{id}` ใต้กุญแจ `songs` อ่านเป็น `#/covers/{id}` ของหัวข้อ `covers`.

**Why:** ui-nav D6 ตั้งใจให้ bookmark และลิงก์ไม่พัง; brief อนุญาตให้เปลี่ยน hash ได้ต่อเมื่อมี redirect.

**Rejected:**
- ไม่มี redirect — bookmark และ "ล่าสุด" ของเจ้าของพังทันที
- เปิด old step hash แล้วไปที่ขั้นที่มันชื่อ — ต้องส่งค่าข้าม `replaceState`; หน้าเปิดที่ขั้นตามสถานะงาน (D5) ซึ่งเป็นขั้นที่ใช่เกือบทุกครั้ง

**Details:**
- hash ที่ไม่รู้จักยังเปิดติดตั้ง (spoil-maker D53)
- `#/sounds?back=#/spoil/review` เดิม: ปุ่มกลับพาไป `#/spoil/review` แล้ว `MOVED` พาไป `#/spoil`

**Accepted risk:** ถอยกลับทำด้วย git revert อย่างเดียว: ล่าสุดที่เขียนใต้กุญแจ `covers` แล้วหายหลัง revert และ bookmark ใหม่ (`#/covers/…`, `#/voices`, `#/spoil/clips`) เปิดติดตั้ง — ยอมได้เพราะแอปใช้คนเดียวบนเครื่องตัวเอง และล่าสุดเป็นแค่ทางลัด (ui-nav D5).

**From:** interview · **Status:** active

## D10: นับคลิกที่ sidebar ตรึง; จอแคบบวก ☰ อีก 1

**Chosen:** "จำนวนคลิก" นับคลิกบนลิงก์หรือปุ่มที่เปลี่ยนสิ่งที่เห็น จากหน้าใดก็ได้ โดยเมนูเป็น sidebar ตรึง (≥1280px); ต่ำกว่า 1280px บวกปุ่ม ☰ อีก 1. เป้า ≤2 สำหรับของที่ใช้บ่อยทุกชิ้นในตาราง spec › Design.

**Why:** brief ขอ "≤2 คลิก จากหน้าไหนก็ได้" แต่ไม่บอกวิธีนับ; ☰ เปิดเมนูเท่านั้น ไม่พาไปไหน จึงแยกบอกให้เห็นทั้งสองขนาด.

**Accepted risk:** ผล render ของสปอยรอบก่อนใช้ 2 คลิก (3 บนจอแคบ) จากเดิม 1 (2) เพราะขั้นไม่มีรายการในเมนู (D5); render ที่เพิ่งเสร็จยังพาไปที่ผลเอง.

**From:** interview · **Status:** active

## D11: หน้าตาใช้ component เดิม ไม่มีจอรอออกแบบ

**Chosen:** ทุกหน้าที่รวมกันใช้ component เดิมของมันวางเรียงในหน้าเดียว; แถบขั้นของสปอยใช้หน้าตาเดิมของ `SpoilSteps`; ปุ่มสลับของ EP ใช้ `SegmentedChoice`. ไม่มี `ui-prompt.md`.

**Why:** งานนี้คือโครงสร้างการเข้าถึง ไม่ใช่การตกแต่ง (brief › ขอบเขต); ทำตามแบบ reels-only D10.

**Rejected:**
- ออกแบบใน Figma ก่อน — ไม่มีจอใหม่ มีแต่การย้ายส่วนเดิม

**From:** interview · **Status:** changed by D15, D16

## D12: seam คือ `App` ใน jsdom และหน้าที่รวมกัน ไม่มี e2e

**Chosen:** พิสูจน์เมนู route และ redirect ผ่าน `App` ใน jsdom (ui-nav D9); พิสูจน์พื้นที่ทำงานผ่าน component ของหน้า (`SpoilMakerPage`, `SongsPage`, `DrumsPage`, `ToonPage`) ใน jsdom กับ `fetch` ที่ stub.

**Why:** test เดิมของทุกหน้าเป็นแบบนี้ และโปรเจกต์ไม่มี e2e package (reels-only D11).

**Rejected:**
- e2e ด้วย Playwright — โปรเจกต์ไม่มี และทุกพฤติกรรมเห็นได้ใน jsdom

**From:** interview · **Status:** active

## D13: ไม่แตะ backend

**Chosen:** API job และการ render เหมือนเดิมทุกตัว; ชื่อ API (`/api/songs`, `/api/spoil-maker/voices`, `lesson`) ไม่เปลี่ยนตามชื่อ route ใหม่.

**Why:** brief › ขอบเขต: งานนี้คือโครงสร้างการเข้าถึง ไม่ใช่การทำงานของงานเรนเดอร์.

**Rejected:**
- เปลี่ยนชื่อ API ให้ตรง route — งาน backend ที่ไม่มีผู้ใช้เห็น และเสี่ยงชนกับ reels-only Open Q1
