# Decisions: sound-library

## D1: คลังเสียงเป็นคลังกลางของทั้งแอป มี tab ของตัวเอง การ์ตูนเล่าและสปอยใช้ร่วมกัน

**Chosen:** "คลังเสียงพื้น" ของ tab การ์ตูนเล่าเปลี่ยนเป็น "คลังเสียง" tab ของตัวเองที่ `#/sounds`; เสียงพื้นชุดเดียวกันใช้ได้ทั้งในช่วงของการ์ตูนเล่าและในคลิปสปอย.

**Why:** ผู้ใช้บอกเอง: หน้า `#/toon/sounds` ที่อยู่ในการ์ตูนเล่าดูเหมือนขั้นที่ซ่อนอยู่ และเสียงพื้นอย่างจิ้งหรีด ฝน ห้องเรียน ใช้ได้กับคลิปทุกแบบ.

**Rejected:**
- คงเป็นหน้าย่อยของการ์ตูนเล่าแล้วให้สปอยมาอ่าน — คลังของ tab หนึ่งที่อีก tab ใช้ หาไม่เจอจาก tab สปอย
- คลังแยกต่อ tab — เสียงเดียวกันต้องเอาเข้าสองครั้ง (เหตุผลเดียวกับ toon D16)

**Details:**
- supersedes toon D16 (คลังกลางของ tab การ์ตูนเล่า): ทุก Series ยังใช้คลังเดียวกันตามเดิม แต่คลังไม่ใช่ของ tab การ์ตูนเล่าแล้ว
- เป็น feature ใหม่เพราะมี tab ข้อมูล และผู้ใช้สองกลุ่ม (การ์ตูนเล่า, สปอย) ของตัวเอง

**From:** change request · **Status:** active

## D2: แถบนำทางมี 6 รายการ ลำดับ ติดตั้ง · คลิป · คลังความรู้ · คลังเสียง · สปอย · การ์ตูนเล่า

**Chosen:** คลังเสียงอยู่ต่อจากคลังความรู้ ก่อนสปอย; ค่าตั้งต้นยังเป็นติดตั้ง.

**Why:** ผู้ใช้กำหนดลำดับเอง: ของที่เตรียมไว้มาก่อน tab ที่สร้างคลิป (ตรงกับเหตุผลของ story-kb D9).

**Rejected:**
- ต่อท้ายหลังการ์ตูนเล่า — ผู้ใช้กำหนดลำดับไว้แล้ว และไม่ตรงลำดับงาน

**Details:**
- changes story-kb D9 (แถบ 4 tab, การ์ตูนเล่าต่อท้ายตาม toon spec › Frontend) เป็น 6 รายการ

**From:** change request · **Status:** active

## D3: แถบ tab แบ่งสามกลุ่มบนจอกว้าง และเป็นปุ่มเมนูบนจอแคบ

**Chosen:** จอกว้างตั้งแต่ 640px ยังเป็นแถบ tab แต่มีเส้นคั่นระหว่างสามกลุ่ม: ติดตั้ง | คลิป · คลังความรู้ · คลังเสียง | สปอย · การ์ตูนเล่า. จอแคบกว่า 640px เป็นปุ่มเดียวที่บอกชื่อหน้าที่เปิดอยู่ กดแล้วเปิดรายการทั้ง 6 เรียงตามกลุ่มพร้อมหัวกลุ่ม.

**Why:** auto mode เลือกตัวเลือกที่แนะนำ: แยก "ของที่เตรียม" ออกจาก "tab ที่สร้างคลิป" ให้เห็นชัดตามที่ผู้ใช้ขอ โดยไม่ต้องรื้อ layout ทุกหน้า; 6 tab ยาวราว 460px ล้นจอ 375px.

**Rejected:**
- เมนูด้านข้างทุกขนาดจอ — ทุกหน้าและทุก frame ใน Figma ต้องเปลี่ยน layout และคอลัมน์ 720px เหลือแคบลง
- 6 tab เรียงเดิมไม่มีกลุ่ม — ไม่ได้แยกส่วนให้ชัดขึ้น และล้นจอแคบ
- แถบเลื่อนแนวนอนบนจอแคบ — tab ท้ายๆ มองไม่เห็นว่ามีอยู่

**Details:**
- หัวกลุ่มในเมนูจอแคบ: "เตรียมของ" (คลิป, คลังความรู้, คลังเสียง) และ "ทำคลิป" (สปอย, การ์ตูนเล่า); ติดตั้งอยู่บนสุดไม่มีหัวกลุ่ม
- จอกว้างไม่มีข้อความหัวกลุ่ม มีแต่เส้นคั่น; screen reader อ่านชื่อกลุ่มจาก `aria-label` ของแต่ละกลุ่ม

**From:** interview (auto mode) · **Status:** active

## D4: ปุ่ม info ข้างหัวข้อ "คลังเสียง" เปิดคำอธิบายสามข้อ

**Chosen:** หัวข้อของหน้าคลังเสียงมีปุ่มไอคอน info กดแล้วเปิดกล่องคำอธิบายใต้หัวข้อ: ใช้ร่วมกับการ์ตูนเล่าและสปอย, เสียงพื้นคืออะไร, เอาเข้าจากไฟล์หรือลิงก์ได้. กดซ้ำ, `Esc` หรือคลิกนอกกล่องปิด.

**Why:** ผู้ใช้ขอเอง เพื่อให้รู้ว่าคลังนี้ใช้ยังไงโดยไม่กินที่บนหน้า.

**Rejected:**
- คำอธิบายเปิดค้างบนหน้า — กินที่ทุกครั้งที่เข้าหน้า ทั้งที่อ่านครั้งเดียวก็รู้

**Details:**
- ข้อความตายตัวอยู่ใน spec › Frontend
- คำเตือนเรื่องสิทธิ์ของเสียง (toon legal ข้อ 4) ยังแสดงตลอดเหนือช่องไฟล์และลิงก์ ไม่ย้ายเข้ากล่องนี้ (toon D56)
- เปิดครั้งแรกปิดอยู่เสมอ ไม่จำว่าเคยเปิด

**From:** change request · **Status:** active

## D5: คลิปสปอยมีเสียงพื้นได้หนึ่งเสียงทั้งคลิป พร้อมความดัง

**Chosen:** หน้าตรวจแก้บทของสปอยเลือกเสียงพื้นจากคลังเสียงได้หนึ่งเสียงต่อ Spoil draft พร้อมความดัง 0–100; เสียงที่สั้นกว่าคลิปวนจากต้นไฟล์; ตั้งต้นคือไม่มีเสียงพื้น.

**Why:** auto mode เลือกตัวเลือกที่แนะนำ: คลิปสปอยยาว 30–180 วินาที (spoil-maker D39) เสียงเดียวพอ และหน้าตรวจแก้ไม่รกขึ้น.

**Rejected:**
- เลือกเสียงต่อประโยคหรือต่อกลุ่มประโยค ผสมทับตอนเปลี่ยนแบบ toon D17 — หน้าตรวจแก้มีช่องต่อประโยคเยอะอยู่แล้ว
- ให้ AI เลือกเสียงตอนร่างบท — Draft job ต้องรู้คลังเสียง และผู้ใช้เลือกเองเร็วกว่าสำหรับเสียงเดียว

**Details:**
- changes spoil-maker D9: "ไม่มีเพลงพื้นหลังในรอบนี้" ไม่จริงแล้ว; เสียงต้นฉบับลดเบาตั้งได้ตามเดิม
- ความดังจำไว้ใน settings ของสปอยแบบ `original_volume` (spoil-maker D40) ตั้งต้น 30 เท่ากับของช่วงในการ์ตูนเล่า
- ร่างใหม่เริ่มที่ไม่มีเสียงพื้นเสมอ: เสียงขึ้นกับเรื่องของคลิปนั้น
- เสียงพื้นตัดที่ท้ายคลิป เหมือนเสียงพื้นของการ์ตูนเล่า

**From:** interview (auto mode) · **Status:** active

## D6: ข้อมูลคลังเสียงย้ายไป `media/sounds/` และ API ย้ายไป `/api/sounds`

**Chosen:** `sounds.json` และ `{id}.m4a` อยู่ที่ `media/sounds/` ของ module `backend.sounds` ที่ไม่ขึ้นกับ toon; backend ย้าย `media/toon/sounds/` มาให้เองครั้งเดียวตอน start; ทุก route ของคลังเสียงย้ายจาก `/api/toon/sounds…` เป็น `/api/sounds…` และเส้นเดิมเลิกใช้.

**Why:** auto mode เลือกตัวเลือกที่แนะนำ: คลังที่ไม่ใช่ของการ์ตูนเล่าไม่ควรอยู่ใต้ folder และ API ของการ์ตูนเล่า; ย้ายเองทำให้เสียงที่ผู้ใช้เอาเข้าแล้วไม่หาย.

**Rejected:**
- คงไว้ที่ `media/toon/sounds/` — สปอยต้อง import ของการ์ตูนเล่า และ folder บอกเจ้าของผิด
- ก๊อปแทนการย้าย — มีสองชุดที่ไม่ตรงกัน
- ให้ผู้ใช้ย้ายเอง — ผู้ใช้ทั่วไปไม่รู้ว่าไฟล์อยู่ไหน

**Details:**
- id `m_` ของเสียงไม่เปลี่ยน: ช่วงของ EP ที่ชี้เสียงอยู่แล้วยังชี้ถูก
- กติกาของ toon D39 (แปลงเป็น m4a), D56 (Sound import), D70 และ D71 (คลังตรงกับไฟล์ m4a) ย้ายตามมาทั้งหมด เปลี่ยนแค่ที่อยู่และ lock
- hash เดิม `#/toon/sounds` เปิดหน้าคลังเสียง (`#/sounds`) แทนหน้าว่าง
- ขั้นตอนย้ายอยู่ใน spec › ข้อมูล

**From:** interview (auto mode) · **Status:** changed by D10, D11

## D7: ลบเสียงที่ยังมีที่ใช้ไม่ได้ ทุก feature ที่อ้างเสียงลงทะเบียนตัวเช็คกับคลังเสียง

**Chosen:** ลบเสียงที่ช่วงของ EP ใด Spoil draft หรือ Render job ที่ยังไม่จบใช้อยู่ → `409` `in_use` พร้อมรายการที่ใช้; การ์ตูนเล่าและสปอยลงทะเบียนตัวเช็คใน `backend.sounds` แบบ Saved voice (ADR-0033) คลังเสียงจึงไม่ import feature ที่ใช้มัน.

**Why:** auto mode เลือกตัวเลือกที่แนะนำ: ไม่มี EP หรือ draft ที่ชี้เสียงที่หายไปเงียบๆ และกติกาเดียวกับ toon D25 ที่ผู้ใช้รู้จักแล้ว.

**Rejected:**
- ลบแล้วล้างเสียงออกจากช่วงและ draft ที่ใช้ — คลิปเปลี่ยนโดยผู้ใช้ไม่ได้สั่ง
- ให้ `backend.sounds` ไปอ่าน EP และ draft เอง — module กลาง import feature ที่ใช้มัน วนกลับทุกครั้งที่มี feature ใหม่

**Details:**
- `in_use` ส่ง `users`: รายการ `{tab, label}` เช่น `{"tab": "toon", "label": "ผีบ้านไม้ · EP 3 คืนฝนตก"}`, `{"tab": "spoil", "label": "Spoil draft: {ชื่อคลิป} · EP {n}"}`
- ลำดับ lock: lock ของ feature (`gpu.slot.draft_lock`, `toon.store.lock`) ก่อน `sounds.lock` เสมอ
- Render job ของสปอยที่ใช้เสียงนับว่าใช้อยู่จนจบ: draft แก้ได้ระหว่าง render (spoil-maker spec › Render job) แต่ ffmpeg ยังอ่านไฟล์อยู่

**From:** interview (auto mode) · **Status:** changed by D11, D12

## D8: Spoil draft ที่ชี้เสียงที่ไม่อยู่ในคลัง render ไม่ได้จนผู้ใช้เลือกใหม่

**Chosen:** เสียงที่ draft ชี้หายจากคลังได้ทางเดียว: การตรวจคลังตอน start ทิ้งรายการเสีย (toon D70). หน้าตรวจแก้บอก "ไม่พบเสียงนี้ในคลังเสียง" และ Render job ตอบ `400` `sound_not_found` จนผู้ใช้เลือกเสียงใหม่หรือ "ไม่มีเสียงพื้น".

**Why:** auto mode เลือกตัวเลือกที่แนะนำ: คลิปไม่ออกมาเงียบโดยผู้ใช้ไม่รู้ และกรณีนี้แทบไม่เกิด.

**Rejected:**
- render ต่อโดยไม่มีเสียงพื้นเงียบๆ — ผู้ใช้ได้คลิปที่ไม่ตรงกับที่เลือก
- ล้าง `sound` ของ draft เองตอน start — draft เปลี่ยนโดยผู้ใช้ไม่ได้สั่ง

**From:** interview (auto mode) · **Status:** changed by D13

## D9: seam สามที่ที่มีอยู่แล้ว: API คลังเสียง, Render job ของสปอย, `App` กับ backend ปลอม

**Chosen:** test ของ feature นี้อยู่ที่ seam เดิมสามที่: `/api/sounds` (ย้ายจาก test คลังเสียงพื้น), `/api/spoil-maker/renders`, และ `App` จริงกับ `testing/testBackend.ts` สำหรับแถบนำทางและหน้าเว็บ.

**Why:** ทุกพฤติกรรมเห็นได้จาก HTTP หรือหน้าเว็บ และทั้งสามมี test กับ fake ครบแล้ว; ไม่ต้องสร้าง seam ใหม่.

**Rejected:**
- test ระดับ `backend.sounds` ตรงๆ — ผูกกับโครงสร้าง module ที่ ticket นี้ย้าย

**From:** code · **Status:** active

## D10: ย้ายคลังเดิมแบบรวมทีละไฟล์ ทำซ้ำได้ทุก start และบอกบนหน้าเมื่อยังเหลือ

**Chosen:** ตอน start ย้ายทั้ง folder เมื่อ `media/sounds/` ยังไม่มีเสียง; มีเสียงทั้งสองที่ → ย้าย m4a ของที่เดิมที่ id ยังไม่มีทีละไฟล์พร้อมรายการ; ล้มกลางทาง start ถัดไปทำต่อ; ยังเหลือเสียงที่เดิม → หน้าคลังเสียงแสดง Alert.

**Why:** red team: แบบเดิมข้ามเมื่อมีเสียงทั้งสองที่ ทำให้เสียงเดิมค้างที่เดิมตลอดไปหลังการย้ายล้มหนึ่งครั้งแล้วผู้ใช้ import เสียงใหม่ และช่วงของ EP ชี้เสียงที่คลังไม่มีโดยไม่มีอะไรบนจอ.

**Rejected:**
- ไม่ย้าย folder ใช้ `media/toon/sounds/` ต่อ — folder บอกเจ้าของผิดตลอดไป (D6)
- ปฏิเสธ Sound import ด้วย `503` จนย้ายครบ — คลังใช้ไม่ได้เพราะปัญหาดิสก์ที่ผู้ใช้อาจไม่รู้

**Details:**
- ขั้นตอนอยู่ใน spec › ข้อมูล › ย้ายจากที่เดิม
- ย้อนกลับไปแอปรุ่นเก่า: ย้าย `media/sounds/` กลับเป็น `media/toon/sounds/` เอง (spec › Ops)

**From:** red team · **Status:** active

## D11: ตัวเช็คลงทะเบียนพร้อม lock และลำดับ; หน้าคลังเสียงกลับไปหน้าที่มาด้วย `back`

**Chosen:** bundle ของ red team ที่แก้ช่องว่างใน D7 และหน้าเว็บ.

**Details:**
- **lock:** ลงทะเบียนเป็น `(rank, lock, check)`; ลบเสียงถือ lock ที่ลงทะเบียนเรียงตาม `rank` แล้วจึง `sounds.lock` แล้วเรียกตัวเช็คที่ไม่ acquire เอง — `backend.sounds` ถือ lock ของ feature ได้โดยไม่ import feature และลำดับตรงกับ `PATCH` ที่ถือ lock ของ feature ก่อน `sounds.exists`
- **ที่เขียน `sound_id`:** `PATCH` ช่วงของ toon, ขั้นเขียนผลของ Cards job, `PATCH /draft` ของสปอย เช็ค `sounds.exists` ใต้ lock ของ feature — Cards job เขียนเสียงที่ AI เลือกลง EP ได้เหมือน `PATCH`
- **`.partial`:** upload, โหลดลิงก์ และไฟล์แปลงของ Sound import ใช้ `media/sounds/.partial/` ที่ `backend.sounds.clean_on_start` ล้างทั้ง folder — เดิมใช้ `media/toon/.partial/` ที่ toon ล้าง
- **กลับ:** `#/sounds?back={hash}` แสดง "← กลับ" เมื่อ hash ขึ้นต้น `#/spoil/` หรือ `#/toon/`; ลิงก์ "← การ์ตูนเล่า" ของหน้าเดิมเลิก — tab กลางไม่ใช่ของการ์ตูนเล่า และ tab สปอยเปิดขั้นแรก ไม่ใช่หน้าตรวจแก้
- **hash เดิม:** `useHash` แทน `#/toon/sounds` ทั้งตอนเริ่มและใน listener ของ `hashchange` ก่อน `setHash`; หน้าชนิด `sounds` ของ toon ถูกลบ — `replaceState` ไม่ยิง `hashchange`
- **ของที่ใช้ร่วมใน frontend:** สิ่งที่หน้าคลังเสียงใช้จาก toon (`CommitField`, `NoticeLine`, `lib/edit`, `lib/notice`, `lib/upload`, `useReadyState`, icon) ย้ายไป `components/ui` และ `lib` ของแอป toon import จากที่นั้น — `features/sound-library` ไม่ import `features/toon`

## D16: ปุ่มเมนูจอแคบ: ชื่อ "เมนู tab: {หน้า}", ปิดเมื่อเลือกรายการใดก็ได้, อยู่แถวใต้ wordmark

**Chosen:** ปุ่มเมนูของจอแคบกว่า 640px เป็นปุ่มแบบเปิดปิด (disclosure: `aria-expanded`, `aria-controls`) ไม่ใช่ `role="menu"`; ชื่อที่ screen reader อ่านคือ "เมนู tab: {ชื่อหน้าที่เปิด}" ข้อความที่เห็นคือชื่อหน้าพร้อมไอคอนเมนู (`components/ui/assets/menu.svg`). รายการเป็น `nav` "เมนู tab" ลอยใต้ปุ่ม: ติดตั้ง แล้วหัวกลุ่มแต่ละกลุ่มกับ tab ของมัน; เลือกรายการไหนก็ปิดเมนู รวม tab ที่เปิดอยู่ (hash ไม่เปลี่ยน หน้าไม่ถูกสร้างใหม่). ปุ่มอยู่แถวที่สองใต้ wordmark ที่แถบ tab เคยอยู่ (wordmark กับปุ่ม action ยังอยู่แถวแรก). จอกว้างเส้นคั่นอยู่หน้าแต่ละกลุ่มใน `role="group"`. กลุ่มของแต่ละ tab อยู่ใน `TABS` (`group` ต้องเป็น id ของ `TAB_GROUPS`) และชื่อกลุ่มใน `TAB_GROUPS` ของ `lib/useHash.ts`. การปิดด้วย `Esc` (focus กลับที่ปุ่ม) และคลิกนอกอยู่ใน `lib/useDismiss.ts` ที่ปุ่ม info ของหน้าคลังเสียง (D4) ใช้ด้วย; `aria-controls` มีเฉพาะตอนเมนูเปิด เพราะรายการไม่อยู่ใน DOM ตอนปิด.

**Why:** ลิงก์ในรายการเป็นลิงก์ `#/…` ธรรมดา ปุ่ม disclosure ไม่บังคับปุ่มลูกศรแบบ `menu`; ชื่อปุ่มต้องมีข้อความที่เห็นอยู่ด้วยแต่ต้องไม่ชนกับปุ่ม "ติดตั้ง" ของหน้าติดตั้ง; ปุ่มเดียวยาวพอจะดัน Refresh ล้นแถวแรกที่ 375px. auto mode: design ของแถบนำทางยัง pending (Blocked #1) จึงสร้างตามแถบ tab เดิม.

**From:** build ticket 02 · **Status:** active
