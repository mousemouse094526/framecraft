# Decisions: reels-only

## D1: แอปไม่มีบทเรียน: อะไรที่มีไว้สอนเอาออก อะไรที่สร้างไฟล์คลิปเก็บ

**Chosen:** ทุกหน้า ปุ่ม ส่วน และคำบนจอ ถามข้อเดียว "มีไว้สอน หรือ มีไว้สร้างไฟล์คลิป?" สร้างคลิป เป็นของที่คลิปใช้ (คลัง) หรือตั้งค่าเครื่อง = เก็บ; สอน อธิบาย หรือสร้างบทเรียน = เอาออกจริง ไม่ใช่ซ่อน.

**Why:** เจ้าของบอกว่า "อยากให้มันใช้ง่ายไม่สับสน อะไรที่เกี่ยวกับบทเรียนเอาออกเลย ไม่ต้องเอามา และอะไรที่เกิน ๆ หลงประเด็นเอาออกเลย" และ "ไม่ได้จะทำบทเรียน".

**Rejected:**
- ซ่อนส่วนบทเรียนไว้หลังตัวเลือก — เจ้าของสั่งเอาออก ไม่ใช่ซ่อน และโค้ดที่ซ่อนไว้ยังต้องดูแล
- เปลี่ยนชื่อ `lesson` เป็น `reel` ทั้งระบบในงานนี้ — `drum_cover` ใช้ `video_gen.lessons` ข้างใน, ไฟล์ `media/drums/lessons/` ของเจ้าของต้องย้าย, เสี่ยงทำทางทำ reel พัง (ดู D8)

**Details:**
- ขยายกฎเมนูของ ui-nav D13 (ADR-0064) จากเมนูไปทุกหน้า
- คำบนจอรวม `aria-label`, หัวข้อ, ป้ายนับ, ข้อความ error ที่ backend ส่งให้หน้าเห็น
- ตรวจทุกหน้าในเมนูแล้ว: นอกจาก D2 กับ D6 ไม่มีอะไรต้องเอาออก (D9)

**From:** interview · **Status:** active

## D2: สอนกลองเป็น "reel กลอง": Groove เล่นซ้ำตามจำนวนรอบ ไม่มีท่อนสอน

**Chosen:** หน้าแก้ที่ `#/drums/{id}` เหลือ หัวเรื่อง บรรทัดรอง คำบรรยาย BPM พื้นหลัง Groove และ "จำนวนรอบ" 1–8 ที่ Groove เล่นซ้ำ; ตัดท่อนสอนทั้งส่วน (ป้าย คำอธิบาย ชิ้นที่เน้น ความเร็ว % เพิ่ม เลื่อน ลบท่อน). ฟังจังหวะ render และผล render ทำงานเหมือนเดิม.

**Why:** เจ้าของบอก "ตัวสอนกลองเอาออกแล้วเปลี่ยนเป็นสร้าง reels กลองแทน ให้แค่สร้าง reels กลองได้พอ"; ทางเลือกนี้เป็น Recommended ที่ auto mode รับ.

**Rejected:**
- เหลือ Groove อย่างเดียว ไม่มีบรรทัดรอง คำบรรยาย จำนวนรอบ — ข้อความบนคลิปกับความยาวคลิปเป็นของ reel ไม่ใช่การสอน
- เก็บท่อนสอนแต่เปลี่ยนชื่อ — ป้าย ชิ้นที่เน้น และความเร็วช้ามีไว้สอนทีละขั้น

**Details:**
- เปลี่ยน video-gen D1 (คลิปสอนกลอง) และ video-gen D4 (ท่อนสอน 1–6) ส่วนที่ผู้ใช้เห็น
- BPM คงเป็นค่าเดียวของทั้ง reel; ความเร็วต่อท่อน (BPM แบบสอน) ไม่มีแล้ว
- รายการ ทำซ้ำ ลบ ของ video-gen D10 คงเดิม เปลี่ยนแค่คำ

**From:** interview · **Status:** active

## D3: นับเข้า 1 ห้องตอนต้นคลิปคงไว้

**Chosen:** ห้องนับเข้า (ไฮแฮทเบา 4 ครั้ง พร้อมหัวเรื่องและบรรทัดรอง, video-gen D13) ยังอยู่ต้นทุก reel กลอง; backend `timeline` ไม่แก้.

**Why:** ไม่มีคำสอนบนจอ เป็นแค่ห้องเปิดที่โชว์หัวเรื่อง และการตัดต้องแก้ `timeline` `captions` ความยาว และ test ของ render ที่ทำงานอยู่; เป็น Recommended ที่ auto mode รับ.

**Rejected:**
- ตัดนับเข้า ให้คลิปเริ่มที่โน้ตแรก — แตะ backend render ที่ใช้อยู่ เสี่ยงทำ reel พัง (task ข้อ 5); ถ้าเจ้าของอยากตัดเป็น change request

**From:** interview · **Status:** superseded by D15

## D4: ข้อมูลและ API ของ reel กลองไม่เปลี่ยน หน้าเว็บส่งท่อนเดียวเสมอ

**Chosen:** `lesson.json`, `/api/drums/lessons` และ `chapters` คงเดิม; หน้าแก้ส่ง `chapters` เป็นท่อนเดียว `{label: "", text: "", focus: [], repeats: n, speed: 100}` ทุกครั้งที่บันทึก. reel ใหม่ที่ backend สร้างเริ่มเป็นท่อนเดียว 4 รอบ.

**Why:** ทางทำ reel ต้องไม่พัง (task ข้อ 5) และ `drum_cover` ใช้ `Lesson`/`Chapter` ข้างใน; ท่อนเดียวที่ไม่มีป้ายแสดงหัวเรื่องกับบรรทัดรองทั้งคลิปอยู่แล้ว (video-gen D12) และทุกชิ้นสว่าง.

**Rejected:**
- เปลี่ยน schema เป็น `repeats` ตัวเดียว — ต้อง migrate ไฟล์เก่าและแก้ `drum_cover`; ได้แค่ชื่อที่สวยขึ้น
- ให้หน้าเว็บส่งท่อนเดิมกลับไปไม่แตะ — reel ที่มีหลายท่อนจะยังมีป้ายสอนบนคลิปโดยผู้ใช้แก้ไม่ได้

**Details:**
- **reel แบบเก่า** (มีมากกว่าหนึ่งท่อน หรือท่อนเดียวที่มีป้าย คำอธิบาย ชิ้นที่เน้น หรือความเร็วไม่ใช่ 100): หน้าแก้โชว์จำนวนรอบ = ผลรวมรอบของทุกท่อน ไม่เกิน 8
- Alert ของ reel แบบเก่าบอกว่าบันทึกแล้ว ป้าย คำอธิบาย ชิ้นที่เน้น และความเร็วของแต่ละท่อนหาย เหลือ Groove {n} รอบที่ BPM เดียว (บอก "จาก {รวม} รอบ" เมื่อถูกตัดที่ 8) และอยากเก็บแบบเดิมให้กดทำซ้ำในรายการก่อน
- reel แบบเก่าที่รวมแล้วยาวเกิน 90 วินาที: บรรทัดความยาวบอกเกินเท่าไหร่ ฟังจังหวะกับ render กดไม่ได้จนลดรอบ (video-gen D16)
- บันทึกระหว่าง render ของ reel นั้นถูกปฏิเสธ 409 แบบเดิม ข้อความขึ้นใต้บันทึก ฟอร์มยังไม่บันทึก (video-gen D22)
- สำเนาก่อนเขียนทับ: D12
- `chapters` ว่างหรือรอบรวม 0 ไม่มี: backend ตรวจ 1–6 ท่อน ท่อนละ 1–8 รอบ (`video_gen.lessons`)
- reel แบบเก่าถูกเขียนใหม่ตอนผู้ใช้กดบันทึก ฟังจังหวะ หรือ render เท่านั้น (ทั้งสามบันทึกก่อน); เปิดดูเฉย ๆ ไม่เขียน
- เปิด reel แบบเก่านับว่ามีที่ยังไม่บันทึก: ปุ่มบันทึกกดได้ ออกจากหน้าแล้วถามก่อน และฟังจังหวะกับ render บันทึกแบบใหม่ก่อน จึงไม่มีคลิปใหม่ที่มีป้ายสอน
- ผล render ที่ทำไว้แล้วไม่แตะ
- ความยาวคลิปบนหน้า (`lengthOf`) ยังคำนวณจาก `chapters` ที่จะส่ง จึงตรงกับ backend เหมือนเดิม
- ค่าตั้งต้นของ reel ใหม่ใน `video_gen.lessons` เปลี่ยนจากสองท่อน (ท่อนสองมีป้าย) เป็นท่อนเดียว 4 รอบ

**From:** interview · **Status:** active

## D5: เมนูเรียก "reel กลอง" hash เดิม

**Chosen:** หัวข้อใหญ่ `drums` ในหมวดดนตรีชื่อ "reel กลอง" รายการ "reel ทั้งหมด" ที่ `#/drums`; `TabId` `drums`, ทุก hash `#/drums…` และล่าสุดของมันเหมือนเดิม จึงไม่ต้องมี `MOVED` (ui-nav D6).

**Why:** เจ้าของเรียก "สร้าง reels กลอง"; คำสั้นแบบหัวข้ออื่น (สปอย แกะเพลง) และ "reel" บอกว่าได้คลิป; hash ไม่เปลี่ยนเพราะ deep link เก่าต้องเปิดได้ (task › ขอบเขต).

**Rejected:**
- "สร้าง reels กลอง" — ยาว และทุกหัวข้อสร้างอยู่แล้ว
- "กลอง" — ไม่บอกต่างจากแกะเพลงที่ก็ทำ reel กลอง
- ย้าย hash เป็น `#/drum-reels` พร้อม `MOVED` — ได้แค่ชื่อ แลกกับงาน redirect

**Details:**
- เปลี่ยน video-gen D9 (ชื่อ tab) และชื่อหัวข้อใน ui-nav D1, D12
- หัวหน้า (`locationOf`) เป็น "reel กลอง / reel ทั้งหมด"
- รายการ reel กลองมีบรรทัดใต้หัวว่าเป็น reel จาก Groove ที่กรอกเอง และ reel จากเพลงทำในแกะเพลง จึงไม่สับสนกับ Reel cover (red team)

**From:** interview · **Status:** active

## D6: หน้าเพลงไม่มีส่วนบทเรียน เหลือทางไป reel cover

**Chosen:** เอาออกจาก `SongPage`: ส่วน "สร้างบทเรียน" (ห้องแรก จำนวนห้อง BPM ของบทเรียน ตารางตัวอย่าง ฟัง สร้างบทเรียนกลอง), ส่วน "บทเรียนจากเพลงนี้", และส่วน "ผลแกะ" ทั้งส่วน (แถบห้องที่พบ `FoundBars`) ที่มีไว้เลือกห้องแรกของบทเรียน. เหลือหัวเพลงกับเครื่องเล่น ช่วงแกะ โหมด แกะโน้ต คำเตือนเรื่องการตีแรก และการ์ด Reel cover.

**Why:** เจ้าของบอก "สร้างบทเรียน ออกให้หมด ไม่ได้จะทำบทเรียน"; แถบห้องที่พบมีไว้เลือกห้องของบทเรียนเท่านั้น (drum-notes D20) การ์ด Reel cover บอกช่วงกับจำนวนการตีแล้ว.

**Rejected:**
- เก็บแถบห้องที่พบไว้ให้กดฟัง — เครื่องเล่นทำได้อยู่แล้ว และข้อความของมันพูดถึงบทเรียน
- ซ่อนส่วนบทเรียนหลังปุ่ม — D1

**Details:**
- แทน drum-notes D11, D12, D21 และส่วนเลือกห้องของ D20; เปลี่ยน drum-notes D2 (แกะเพลงจบที่ reel ไม่ใช่บทเรียน) และ D28 (ชื่อบทเรียนจากรายการ)
- แทน ADR-0047 ด้วย ADR-0065
- การ์ด Reel cover ขึ้นทุกครั้งที่มี `analysis` รวมเพลงที่ไม่มีห้อง 4/4: reel cover ใช้เวลาจริงของการตี ไม่ต้องการห้อง 4/4 (ADR-0051) จึงไม่มีข้อความ `NO_FOUR_FOUR` อีก; ไม่พบการตีเลยยังมีคำเตือนเดิม (drum-cover D9)
- `bars` ใน `GET /api/songs/{id}` คงไว้: `lateStart` (drum-cover D9, D19) ใช้มัน
- `useListen` คงไว้: หน้า reel กลองกับหน้า reel cover ใช้ (drum-cover อ้าง drum-notes D21 เป็นแบบของปุ่มนี้)

## D7: ลบโค้ดและ route ที่มีไว้สร้างบทเรียนจากเพลงเท่านั้น

**Chosen:** ลบ module `drum_notes.lesson`, route `POST /api/songs/{id}/preview`, `/listen`, `/lessons`, field `lessons` ของ `Song` และ `SongRow`, `songs.add_lesson` กับการกรองบทเรียนที่หาย; ฝั่งหน้าเว็บลบ hook `useLessonPreview` `useLessonTitles` กับส่วน lesson ของ `drum-notes/lib/songs`. test ของสิ่งที่ลบลบตาม.

**Why:** task ข้อ 2 "ลบ section ปุ่ม และโค้ดที่เหลือใช้เฉพาะมัน".

**Rejected:**
- เก็บ route ไว้เผื่อ — ไม่มีใครเรียก และ D1 ไม่ให้มีบทเรียน

**Details:**
- `song.json` เก่าที่มี `lessons` อ่านได้: pydantic ข้าม key ที่ไม่รู้จัก (`extra` ตั้งต้นเป็น `ignore`); key หายตอนเพลงถูกเขียนครั้งหน้า
- `drum_notes.score` และ `drum_notes.groove` คงไว้: Pick job และ `drum_cover.timeline` ใช้
- บทเรียนที่เคยสร้างจากเพลงอยู่ต่อใน `media/drums/lessons/` เป็น reel กลองธรรมดา (ADR-0047 ทำให้มันไม่รู้จักเพลงอยู่แล้ว)
- route ที่ลบตอบ 404 หรือ 405 ตามที่ FastAPI ตอบ route ที่ไม่มี

**Sources:** [Pydantic — Configuration › extra](https://docs.pydantic.dev/latest/api/config/#pydantic.config.ConfigDict.extra)

## D8: เปลี่ยนแค่คำบนจอ ชื่อในโค้ดที่มีคำว่า lesson คงไว้

**Chosen:** ข้อความทุกตัวที่ผู้ใช้เห็น (หน้าเว็บ และ `message` ที่ backend ส่งให้หน้าเว็บโชว์) ที่พูดถึง บทเรียน สอน หรือท่อนสอน เปลี่ยนเป็นคำของ reel; identifier `lesson`, `Lesson`, `lessons_dir`, `media/drums/lessons/`, `/api/drums/lessons`, `chapters`, `video_gen.lessons`, ชื่อ component และ test คงเดิม และอยู่ในรายการ spec.md › Open Questions 1.

**Why:** task ข้อ 5: รื้อชื่อทั้งระบบเสี่ยงทำ reel พังและแตะไฟล์ของเจ้าของ; ผู้ใช้ไม่เห็นชื่อในโค้ด.

**Rejected:**
- เปลี่ยนชื่อในโค้ดฝั่งหน้าเว็บอย่างเดียว — ครึ่ง ๆ กลาง ๆ ทำให้หน้าเว็บกับ API ใช้คนละคำ

**Details:**
- `render` `timeline` `captions` ของ video-gen แก้ได้แค่ string ที่ผู้ใช้เห็น เช่น `NOT_RUNNING`
- comment ที่บรรยายพฤติกรรมที่เปลี่ยน (เช่น "ท่อนสอน 1–6") แก้ให้ตรงของจริงในไฟล์ที่แตะ

## D9: ตรวจหน้าอื่นแล้ว ไม่มีอะไรเกินต้องเอาออก

**Chosen:** คลังคลิป คลังความรู้ คลังเสียง เสียงที่บันทึก สปอย การ์ตูนเล่า แกะเพลง หน้า reel cover และติดตั้ง ผ่านเกณฑ์ D1 ทั้งหมด จึงไม่เอาออก.

**Why:** ทุกหน้าเดินไปถึงไฟล์คลิป เป็นของที่คลิปใช้ หรือตั้งค่าเครื่อง (ADR-0064); ไม่มีหน้าไหนมีไว้สอน.

**Details:**
- **แกะเพลง:** เอาเพลงเข้าและแกะโน้ตให้ reel cover (drum-cover) กับ reel คาลิมบา (kalimba-cover) — เก็บ ตัดแค่ส่วนบทเรียน (D6)
- **คำใบ้โหมดทำนอง** (`MELODY_HINT`) พูดถึง "groove พื้นฐาน" ของบทเรียน: build เขียนใหม่ให้บอกสิ่งที่ reel ได้จากโหมดนี้ (ตรวจกับ `drum_cover` และ `kalimba_cover` ก่อนเขียน)
- **คำเตือนลบเพลง** "บทเรียนกลองที่สร้างจากเพลงนี้ยังอยู่" เอาประโยคนั้นออก

## D15: reel กลองไม่มีนับเข้า คลิปเริ่มที่ห้องแรกของ Groove

**Chosen:** ตัดห้องนับเข้าออกจาก reel กลอง: เฟรมแรก (t = 0) คือ beat 1 ของห้องแรกของ Groove; ไม่มีไฮแฮทเบา 4 ครั้ง ไม่มีตัวนับ 1–4 ก่อน Groove. แทน D3 และส่วน **นับเข้า** ของ video-gen D13.

**Why:** เจ้าของเห็นคลิปจริงแล้วตอบ Open Question 2: "merge แล้ว ตัดนับเข้าด้วย".

**Rejected:**
- เว้นช่วงเงียบสั้น ๆ ก่อนโน้ตแรก — เจ้าของต้องการให้คลิปเริ่มที่ห้องแรกของบทเลย; ช่วงเงียบคือนับเข้าที่ไม่มีเสียง
- ตัดแค่เสียง tick เก็บห้องว่างไว้ — คลิปยังยาวขึ้น 1 ห้องเหมือนเดิม

**Details:**
- **ความยาว:** `length_s` = ทุกท่อน + หางเสียง 1.5 วินาที (แทนสูตรของ video-gen D21 ที่มีนับเข้า); สั้นลง 4 beat ที่ความเร็วของท่อนแรก. reel ใหม่ (100 BPM 1 ห้อง 4 รอบ) จาก 13.5 เป็น 11.1 วินาที = 333 เฟรม. mp4, wav ของฟังจังหวะ จำนวนเฟรม `percent` ค่าประมาณดิสก์ และเพดาน 90 วินาที ใช้ค่าใหม่นี้ค่าเดียว (video-gen D21 ยังเป็นกฎ "ค่าเดียว")
- **หน้าเว็บ:** `lengthOf` ตัดห้องนับเข้าแบบเดียวกัน (keep the two alike); ความยาวในรายการมาจาก backend `length_s`
- **หัวเรื่องกับบรรทัดรอง:** ไม่มีส่วนหัวของนับเข้าแล้ว ส่วนแรกคือท่อนแรกตั้งแต่ 0. reel ทุกตัวที่หน้าเว็บบันทึกเป็นท่อนเดียวไม่มีป้าย (D4) จึงขึ้นหัวเรื่องกับบรรทัดรองทั้งคลิป (video-gen D12) ไม่ต้องย้ายอะไร. lesson หลายท่อนที่ส่งตรงทาง API (test เท่านั้น) ขึ้นป้ายของท่อนแรกตั้งแต่ 0
- **`.srt`:** cue แรกเริ่ม `00:00:00,000` เป็นของท่อนแรก ไม่มี cue ของนับเข้า; reel ท่อนเดียวมี cue เดียวทั้งคลิป
- **ตัวนับและเลข beat:** beat แรกที่ 0 คือ 1 (`BAR` บนเลน) ของห้องแรก; จำนวน beat = รอบ × ห้อง × 4
- **เลนโน้ต:** ไม่มี segment ของนับเข้า; segment แรกคือท่อนแรก. โน้ตที่ step 0 อยู่บน playhead ตั้งแต่เฟรมแรก
- **ไม่มีเสียง tick:** ไม่มี hit ชนิด `count` อีก; `COUNT_IN_PIECE` และการกรอง hit นับเข้าใน `frames` ลบ; round-robin ของไฮแฮทปิดชั้นเบาเริ่มนับจากโน้ตจริงตัวแรก
- **reel cover (drum-cover) และ reel คาลิมบา (kalimba-cover) ไม่ได้รับผล:** timeline ของมันสร้างใน `drum_cover.timeline.build` และ `kalimba_cover.timeline.build` จากเวลาจริงของการตี (ADR-0051) ไม่ผ่าน `video_gen.timeline.build`, `length_s`, `captions.sections` หรือ `lane.segments`; ใช้ร่วมแค่ `assemble` `to_sample` `beat_s` `TAIL_S` ซึ่งไม่มีนับเข้า และไม่เคยมีนับเข้า (drum-cover D3). comment "no count-in's speed change" ใน `drum_cover/timeline.py` เขียนให้ไม่อ้างนับเข้า
- ผล render ที่ทำไว้แล้วไม่แตะ; render ใหม่ของ reel เดิมได้คลิปที่สั้นลง
- **ไม้กลองตีแรก:** โน้ตที่ step 0 ถูกตีที่ t = 0 จึงเฟรมแรกไม้อยู่บนชิ้นนั้นแล้ว ไม่เห็นไม้ยกขึ้นก่อนตีแรก (rise 0.12 วิ ของ video-gen D13 เริ่มก่อนคลิป); รับได้ เพราะเจ้าของต้องการให้คลิปเริ่มที่ห้องแรกเลย และช่วงยกไม้คือ lead-in ที่ถูกปฏิเสธข้างบน (red team, Breaker)
- **flam ที่ต้นคลิป:** D16
- **round-robin:** ไม่มี tick ของไฮแฮทปิดชั้นเบาแล้ว ไฮแฮท ghost กับโน้ตนำของ flam จึงวนลำดับ sample ต่างจากเดิม; render ใหม่ของ reel เดิมได้ wav ต่างจากผลเก่า แต่ render ซ้ำของโค้ดเดียวกันยังได้ไฟล์เดิม (video-gen D13 › ความแรง)
- **เพดาน 90 วินาที:** reel ที่ยาวเกินไม่เกินหนึ่งห้องของท่อนแรก ซึ่งเดิมถูกปฏิเสธ ตอนนี้ render ได้; `lengthOf` ของหน้าเว็บเปลี่ยนใน commit เดียวกับ backend เพื่อให้สองฝั่งบอกค่าเดียวกัน
- **ทางถอย:** revert commit; ไม่มีข้อมูลต้อง migrate (`lesson.json` ไม่เปลี่ยน ผล render เก่าเก็บ `length_s` ของมันเอง)

## D16: flam ที่ step แรกของต้นคลิปเล่นแค่โน้ตหลัก

**Chosen:** โน้ตนำของ flam ที่จะตกก่อน t = 0 (flam ที่ step 0 ของรอบแรกของท่อนแรก) ไม่เล่น; โน้ตหลักเล่นที่ 0 ตามปกติ. flam ที่ step 0 ของรอบถัดไปมีโน้ตนำครบ.

**Why:** ไม่มีนับเข้าแล้ว โน้ตนำ (0.03 วิ ก่อนโน้ตหลัก, video-gen D13) ตกที่ −0.03 วิ = sample −1323 ซึ่ง `mixer` วางเป็น slice จากท้าย array แล้วพัง (red team, Breaker); เป็น Recommended ที่ auto mode รับ.

**Rejected:**
- เลื่อนทั้งคลิปช้าลง 0.03 วิ เมื่อมี flam ต้นคลิป — t = 0 ไม่ใช่ beat 1 และ `length_s` ต้องมีกรณีพิเศษสองฝั่ง
- บีบโน้ตนำมาที่ 0 พร้อมโน้ตหลัก — ฟังเป็นตีซ้อน ไม่ใช่ flam

**Details:**
- กฎอยู่ใน `timeline.build` ที่เดียว: hit ที่เวลา < 0 ไม่ถูกใส่; `mixer` `frames` `captions` ไม่ต้องรู้
- `length_s` ไม่เปลี่ยน; flam แรกบนเลนไม่มีหัวโน้ตเล็กกับวงแหวนเล็กของโน้ตนำ โน้ตหลักเหมือนเดิม
- `drum_cover` ไม่มี flam จึงไม่ได้รับผล
