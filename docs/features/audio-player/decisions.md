# Decisions: audio-player

## D1: เครื่องเล่นเสียงตัวเดียวของทั้งแอป เล่นได้ทีละเสียง

**Chosen:** ทุกปุ่มฟังเสียงเล่นผ่านเครื่องเล่นเสียงตัวเดียว (module ร่วมใน `lib/` ที่ถือ `HTMLAudioElement` ตัวเดียว). เริ่มเสียงใหม่ = เสียงที่เล่นอยู่หยุดก่อนเสมอ.

**Why:** เจ้าของบอกว่า "มันกดฟังซ้ำและทำให้มันเล่นซ้ำๆทับกันได้"; `playAudio` สร้าง `<audio>` ใหม่ทุกครั้งที่กดจึงเล่นซ้อนได้.

**Rejected:**
- แก้ `playAudio` ให้จำตัวเก่าแล้ว stop — ยังไม่มี pause และเวลา ต้องรื้ออีกรอบ
- React context พร้อม provider ที่ `App` — ทุก test ของหน้าต้องห่อ provider; module ตัวเดียวพอสำหรับแอปผู้ใช้คนเดียว
- `<audio controls>` ของ browser ทุกที่ — หน้าตาไม่เข้าชุด และไม่บังคับทีละเสียง

**Details:**
- module อ่านจาก React ผ่าน `useSyncExternalStore` (React 19) ไม่มี provider.
- `playAudio` และ `lib/audio.ts` ถูกลบเมื่อไม่มีผู้ใช้เหลือ.

**From:** interview · **Status:** active

## D2: กดปุ่มเดิม = หยุดชั่วคราวและเล่นต่อ; สลับเสียงแล้วกลับมา = เริ่มจากต้น

**Chosen:** กดปุ่มของเสียงที่กำลังเล่น = หยุดชั่วคราว; กดอีกครั้ง = เล่นต่อจากตำแหน่งเดิม. เมื่อเสียงอื่นเริ่ม เสียงเดิมหยุดและลืมตำแหน่ง กดกลับมาเริ่มจากต้น. เล่นจบ = กลับเป็นพร้อมเล่น กดอีกครั้งเริ่มจากต้น.

**Why:** เจ้าของขอ "กด play และ pause"; เครื่องเล่นจำได้แค่เสียงเดียว (D1) จึงไม่ต้องเก็บตำแหน่งต่อปุ่ม.

**Rejected:**
- จำตำแหน่งของทุกเสียงที่เคยเล่น — ต้องเก็บ state ต่อปุ่ม ซับซ้อนกว่าที่เจ้าของขอ

**From:** interview (auto mode เลือกข้อ Recommended) · **Status:** active

## D3: ปุ่มเล่นร่วม `PlayButton`: ไอคอน play/pause แทนคำว่า "ฟัง"

**Chosen:** ทุกจุดฟังเสียงใช้ component เดียว `PlayButton` ใน `components/ui/`: ไอคอน play เมื่อพร้อมเล่นหรือหยุดชั่วคราว, ไอคอน pause เมื่อกำลังเล่น. ไม่มีคำว่า "ฟัง" เปล่า ๆ บนจอ. ปุ่มที่ต้องผสมเสียงก่อน (D7) มีคำบอกเพิ่มข้างไอคอน: "ฟังจังหวะ" ของ reel กลอง, "ฟัง reel" ของ reel cover.

**Why:** เจ้าของบอกว่าปุ่ม "ฟัง" "ดูแปลกๆ มันควรเป็นเครื่องหมาย กด play และ pause" และให้ "ฟัง" เหลือเฉพาะที่สื่อความหมาย; ปุ่มผสมเสียงทำงานมากกว่าเล่น (บันทึก แล้วผสม) จึงต้องมีคำ.

**Rejected:**
- คงคำ "ฟัง" ทุกปุ่มแล้วเติมไอคอน — เจ้าของบอกว่าคำเปล่า ๆ ดูแปลก
- ไอคอนอย่างเดียวรวมถึงปุ่มผสมเสียง — ข้างปุ่ม "บันทึก" กับ "render reel" ไอคอนเดียวไม่บอกว่าจะบันทึกและผสมก่อน

**Details:**
- ปุ่มที่เคยเป็นข้อความ (เสียงพากย์ ประโยค การ์ด) ใช้หน้าตา `OUTLINE_BUTTON` หรือ `GHOST_BUTTON` เดิมของจุดนั้น; ปุ่มที่เคยเป็นไอคอน (คลังเสียง เสียงพื้น) คงกรอบไอคอนเดิม.
- เป้ากด 44px ต่ำกว่า 640px ตามขนาดเดิมของแต่ละจุด (sound-library D18).

**From:** interview · **Status:** active

## D4: ชื่อปุ่มสำหรับ screen reader เปลี่ยนตามสถานะ ไม่ใช้ `aria-pressed`

**Chosen:** `aria-label` เป็น "ฟัง {สิ่งที่เล่น}" เมื่อพร้อมเล่นหรือหยุดชั่วคราว และ "หยุดชั่วคราว {สิ่งที่เล่น}" เมื่อกำลังเล่น เช่น "ฟัง ลมพัด" / "หยุดชั่วคราว ลมพัด". ไม่ใส่ `aria-pressed`.

**Why:** แนวทาง WAI-ARIA ของ toggle button บอกว่าถ้าใช้ `aria-pressed` ชื่อปุ่มต้องไม่เปลี่ยน; ชื่อที่เปลี่ยนบอกการกระทำถัดไปตรงกว่า และ "ฟัง {ชื่อ}" ตรงกับชื่อเดิมของคลังเสียงและเสียงพื้น.

**Rejected:**
- ชื่อคงที่ + `aria-pressed` — ต้องเลือกอย่างใดอย่างหนึ่งตามแนวทาง และ "กด = เล่นอยู่" อ่านแล้วงงกับ pause
- "เล่น" / "หยุด" — "หยุด" ฟังเหมือนหยุดถาวร แต่ปุ่มนี้เล่นต่อได้

**Details:**
- ชื่อของปุ่มผสมเสียงขึ้นต้นด้วยคำที่เห็นบนจอ ("ฟังจังหวะ", "ฟัง reel") ตามหลัก label-in-name.
- ระหว่างผสม ปุ่มชื่อ "กำลังผสมเสียง…" และกดไม่ได้ (D7).

**Sources:** [WAI-ARIA APG Button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/)

**From:** interview · **Status:** active

## D5: เวลาบนปุ่ม: เล่นไปแล้ว / ยาวทั้งหมด

**Chosen:** ข้างไอคอนแสดง `m:ss / m:ss` (เช่น `0:03 / 0:12`) ตัว mono เมื่อกำลังเล่นหรือหยุดชั่วคราว; ยังไม่รู้ความยาว แสดงแค่เวลาที่เล่นไป แล้วเติมความยาวเมื่อรู้. พร้อมเล่นและผู้เรียกรู้ความยาวอยู่แล้ว แสดงความยาว `0:12`; ไม่รู้ แสดงไอคอนอย่างเดียว.

**Why:** เจ้าของขอ "มี time"; ย้ำว่าเวลาเป็นของแถม play/pause ต้องครบทุกที่ก่อน.

**Rejected:**
- แถบความคืบหน้าลากได้ — เจ้าของไม่ได้ขอ และทำให้ปุ่มกว้างในแถวที่แน่นอยู่แล้ว

**Details:**
- เวลาเป็นงาน ticket หลัง play/pause ครบทุกจุด (ตามคำย้ำของเจ้าของ).
- เกิน 59:59 ไม่มีในแอป ไม่ต้องรองรับชั่วโมง.
- เวลาอยู่ใน `aria-hidden`: screen reader อ่านชื่อปุ่มเท่านั้น ไม่อ่านเลขที่เปลี่ยนทุกวินาที.

**From:** interview · **Status:** changed by D13

## D6: เสียงหยุดเมื่อปุ่มของมันหายไป

**Chosen:** เสียงที่เล่นอยู่หยุดเมื่อปุ่มที่เล่นมัน unmount (ออกจากหน้า, ปุ่มถูกซ่อน) หรือเมื่อ URL ของปุ่มนั้นเปลี่ยน (เสียงตัวอย่างใหม่, ประโยคสร้างเสียงใหม่).

**Why:** เสียงที่ไม่มีปุ่ม pause บนจอหยุดไม่ได้; `useListen` เดิมก็หยุดเมื่อ unmount (video-gen D8).

**Rejected:**
- เล่นต่อข้ามหน้าเหมือน `playAudio` เดิม — ไม่มีที่ให้กดหยุด

**From:** interview · **Status:** changed by D13

## D7: ปุ่มผสมเสียง: ผสมครั้งเดียวต่อชุดค่า แล้วเป็น play/pause

**Chosen:** `useListen` เก็บ wav ที่ผสมแล้วพร้อมกุญแจของค่าที่ใช้ผสม. กดครั้งแรก = "กำลังผสมเสียง…" (กดไม่ได้) แล้วเล่น. กดอีกครั้งขณะค่ายังเหมือนเดิม = pause/เล่นต่อผ่านเครื่องเล่นตัวเดียว ไม่ขอ backend ใหม่. ค่าเปลี่ยน = กดครั้งต่อไปผสมใหม่ และทิ้ง blob เก่า.

**Why:** เจ้าของขอให้ปุ่มบอกสถานะช่วงผสม "แล้วกลายเป็น play/pause ที่กดได้ ไม่ใช่ยิงซ้ำซ้อน".

**Rejected:**
- ผสมใหม่ทุกครั้งที่กด (แบบเดิม) — ไม่มี pause และยิง backend ซ้ำ
- ผสมใหม่เฉพาะเมื่อเล่นจบ — แก้ Groove แล้วกดยังได้เสียงเก่า

**Details:**
- กุญแจคือค่าในฟอร์มที่ผู้เรียกส่งมา (reel กลอง: ช่องของบทเรียน; reel cover: draft) เทียบเป็นข้อความ JSON.
- ระหว่างผสม ถ้าผู้ใช้เริ่มเสียงอื่น wav ที่ผสมเสร็จไม่เล่นเอง: ปุ่มกลับเป็นพร้อมเล่น กดแล้วเล่นทันทีโดยไม่ผสมใหม่ (ไม่มีเสียงที่ผู้ใช้ไม่ได้สั่ง).
- ขอ backend ล้มเหลว แสดง `RefusedAlert` เหมือนเดิม; endpoint และ blob flow ไม่เปลี่ยน (D11).

**From:** interview · **Status:** changed by D13

## D8: ตัวเล่นวิดีโอและ `<audio controls>` เข้ากฎทีละเสียงโดยไม่รื้อ

**Chosen:** เครื่องเล่นเสียงฟังเหตุการณ์ `play` ของทุก media ในหน้า (ฟังแบบ capture ที่ `document`). media อื่นเริ่มเล่น = เสียงของเครื่องเล่นหยุดชั่วคราว; เครื่องเล่นเริ่มเสียง = media อื่นที่เล่นอยู่ถูก pause. ตัวเล่นวิดีโอ (Transcript, ตัดช่วง, ShotPicker, ผล render) และเสียงเพลงของหน้า reel cover ไม่แก้โค้ด.

**Why:** เจ้าของขอ "เล่นทีละเสียงทั้งแอป" แต่สั่งห้ามรื้อตัวเล่นวิดีโอ; เหตุการณ์ `play` ไม่ bubble แต่จับได้ตอน capture จึงครอบได้จากที่เดียว.

**Rejected:**
- เปลี่ยนตัวเล่นวิดีโอให้เรียกเครื่องเล่นเสียง — รื้อตัวเล่นวิดีโอ ซึ่งอยู่นอกขอบเขต
- ไม่ครอบ media อื่น — เพลงต้นฉบับกับปุ่มฟังเล่นทับกันได้ ขัดกับ "ทั้งแอป"

**Details:**
- `<video muted>` ภาพตัวอย่างผล render สปอย ไม่มีเสียง ไม่ถูกนับ (ไม่ pause มัน).
- ตัวเล่นวิดีโอที่ถูก pause เล่นต่อได้ด้วยปุ่มของมันเอง.

**Sources:** [MDN: HTMLMediaElement play event](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play_event)

**From:** interview (auto mode เลือกข้อ Recommended) · **Status:** changed by D13

## D9: เล่นไม่ได้ = กลับเป็นพร้อมเล่น ไม่มีข้อความ

**Chosen:** `play()` ถูกปฏิเสธ ไฟล์หาย หรือ media error → เครื่องเล่นกลับเป็นพร้อมเล่น ไม่แสดงข้อความ (ยกเว้นปุ่มผสมเสียงที่ backend ปฏิเสธ ซึ่งแสดง `RefusedAlert` เหมือนเดิม).

**Why:** คงพฤติกรรมเดิมของ `playAudio` ("A blocked autoplay, a missing file or a browser without audio output only means no sound").

**Rejected:**
- แสดงข้อความ "เล่นเสียงไม่ได้" — เพิ่มข้อความใหม่ที่เจ้าของไม่ได้ขอ

**From:** code · **Status:** changed by D13

**Chosen:** endpoint เดิมทั้งหมด (`POST …/listen`, `design_preview`, ไฟล์เสียงในคลัง, เสียงประโยค เสียงการ์ด) และ blob flow เดิม; งานนี้แก้แค่ `frontend/`.

## D12: seam: เครื่องเล่นกับ `PlayButton` ใน jsdom และ test ของหน้าเดิม

**Chosen:** seam หลักคือ module เครื่องเล่นเสียงกับ `PlayButton` ทดสอบใน jsdom (stub `HTMLMediaElement.prototype.play`/`pause` และยิง event `timeupdate` `loadedmetadata` `ended` `play` เอง). test ของหน้าที่ใช้ปุ่มเดิมแก้ให้หาปุ่มใหม่. ไม่มี e2e.

**Why:** โปรเจกต์ไม่มี e2e (nav-ia D12); jsdom ไม่เล่นเสียงจริง จึงต้องพิสูจน์กฎทีละเสียงที่ตัว module.

**Rejected:**
- e2e ใน browser จริง — โปรเจกต์ยังไม่มีเครื่องมือ และพฤติกรรมพิสูจน์ได้ด้วย event ที่ยิงเอง

**From:** interview · **Status:** active

## D13: ข้อแก้ red team

**Chosen:** ข้อกำหนดที่ red team ชี้ ทั้ง race ของ `play()` กุญแจของปุ่มผสมเสียง และกฎ media อื่น; แก้ D5 D7 D8 D9.

**Details:**
- **สถานะเล่น:** `toggle` ตั้งสถานะเป็นกำลังเล่นทันทีที่เรียก `play()` และตั้ง `currentTime = 0` เองเมื่อเปลี่ยนเสียง; ทุก `toggle`/`release` เพิ่มเลขรอบ (generation); reject ของ `play()` (รวม `AbortError`) `ended` และ `error` ที่เลขรอบไม่ใช่รอบปัจจุบันไม่มีผล; `AbortError` ไม่มีผลเสมอ — เปลี่ยน `src` ระหว่าง `play()` ค้างทำให้ promise เก่า reject และห้ามล้างสถานะของเสียงใหม่ (แก้ D9).
- **กดระหว่าง `play()` ค้าง:** นับเป็นกดขณะเล่น = หยุดชั่วคราว — ปุ่มแสดงสถานะเดียวกับที่ผู้ใช้เห็น.
- **media อื่นทุกตัว:** กฎเดียว: media ใดที่ไม่ `muted` เริ่มเล่น ทุก media อื่นที่กำลังเล่นหยุดชั่วคราว รวมวิดีโอกับวิดีโอ; เครื่องเล่นเริ่มเสียง → `pause()` ทุก `audio`/`video` ในหน้าที่เล่นอยู่และไม่ `muted` (จาก `toggle` เอง เพราะ element ของเครื่องเล่นไม่อยู่ใน document); capture listener ข้าม element ของเครื่องเล่น (แก้ D8).
- **เวลา:** แสดงเฉพาะตอนกำลังเล่นและหยุดชั่วคราว; พร้อมเล่นไม่มีเวลา — คลังเสียงแสดงความยาวของมันเองอยู่แล้ว และเจ้าของบอกว่าเวลาเป็นของแถม; รูปแบบ `m:ss` ปัดลงทั้งวินาที (แก้ D5).
- **กุญแจของปุ่มผสมเสียง:** `useListen(request, { key, unsaved, disabled })` — `key` คือค่าที่บันทึกแล้วที่ backend อ่านตอนผสม (reel กลอง: id กับ `saved` ของบทเรียน; reel cover: `fieldsOf(saved)` กับเวลาแกะของเพลง) ไม่ใช่ draft ที่กำลังพิมพ์ จึงไม่เปลี่ยนเพราะ backend ปัดรูปค่าหลังบันทึก (แก้ D7).
- **กดปุ่มผสมเสียง:** มี wav ของปุ่มนี้ และ `!unsaved` และ `key` เท่ากับกุญแจตอนผสม → toggle ไม่บันทึกไม่ผสม (เล่นจบแล้วกด = เล่น wav เดิมจากต้น); อื่น ๆ → บันทึกและผสมใหม่ (request เดิม); wav ที่ได้เล่นเสมอเมื่อปุ่มยังอยู่ (ตัดกฎ "ไม่เล่นเองถ้าเสียงอื่นเริ่มระหว่างรอ" — ผู้ใช้กดเอง และ D1 หยุดเสียงอื่นอยู่แล้ว) (แก้ D7).
- **แก้ค่าระหว่างฟัง:** `unsaved` เป็นจริงหรือ `key` เปลี่ยนขณะ wav ของปุ่มเป็นเสียงปัจจุบัน → `release` (ปุ่มกลับพร้อมเล่น) แล้ว revoke blob; unmount → `release` revoke และล้าง cache พร้อมกัน จึงไม่มี URL ที่ revoke แล้วค้างหลัง StrictMode remount (แก้ D6, D7).
- **ปุ่มกลายเป็นกดไม่ได้ขณะเล่น** (ปิดเสียงกลอง, reel เกิน 90 วิ): `release` เหมือนปุ่มหายไป (แก้ D6).
- **test:** module เครื่องเล่น export ฟังก์ชัน reset สำหรับ test (หยุด ทิ้ง element ล้างสถานะ ถอด listener) เรียกใน `test-setup.ts` `afterEach` หลัง `cleanup()`.
