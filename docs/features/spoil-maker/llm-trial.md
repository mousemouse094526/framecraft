# ลอง LLM ในเครื่องเขียนบทสปอยไทย

ลองโมเดล 3 ตัวบน Mac M2 RAM 16 GB เมื่อ 2026-10-31 เพื่อเลือก LLM ที่เขียนบทและจับคู่ภาพ (map: LLM ในเครื่องตัวไหนเขียนบทและจับคู่ภาพ). รันด้วย mlx-lm 0.32.2 และ mlx-vlm 0.7.11 ใน venv แยกนอก project แล้วลบทิ้งหลังลอง.

## วิธีลอง

- ต้นฉบับ: Temp clip `f7jkZXvaB4g` (Night of the Living Dead 1968, 96 นาที, public domain) Transcript ภาษาอังกฤษ 883 บรรทัด ราว 26,000 token
- คำสั่ง: เขียนบทสปอยไทยสไตล์เล่าละคร (hook, เรื่อง, หักมุม, คำถามท้าย) ราว 600 ตัวอักษร 10–14 ประโยค แต่ละประโยคบอก id ของบรรทัดที่ภาพตรงกับเนื้อหา ตอบเป็น JSON
- ส่ง Transcript ทั้งเรื่องในครั้งเดียว, `temperature` 0.7, ปิด thinking
- ภาพ: ดึง 3 เฟรม (นาที 10, 45, 80) ให้โมเดลที่ดูภาพได้บรรยายเป็นไทย

- Qwen3.5 9B: เห็นคนวิ่งหนีจากบ้าน, คนถือปืนในห้องมืด, คนใส่สูทคุยกันข้างรถ: ตรงกว่า

## สรุป

- Qwen3.5 9B ดีที่สุด: บทเกือบตามความยาวเป้าหมาย, เล่าเรื่องจริงได้, ดูภาพได้แม่นกว่า. ร่างบททั้งหนัง 96 นาทีได้ในครั้งเดียวราว 4–5 นาที ใช้ memory ราว 10 GB จึงรันพร้อมงาน GPU อื่น (Whisper, OmniVoice) ไม่ได้
- Gemma 4 E4B เร็วกว่า 2 เท่าแต่บทสั้นและไม่เล่าเรื่อง
- Typhoon 2.5 4B ทำตามรูปแบบ JSON ไม่ได้กับ Transcript ยาว
- จับคู่ประโยคกับภาพจาก Transcript อย่างเดียวได้ราวครึ่งหนึ่ง: ข้อมูลสำหรับคำถาม "AI เห็นอะไรของต้นฉบับ"
- ทุกตัวเขียนไทยยังต้องแก้ ตรงกับ D4 ที่ให้ผู้ใช้แก้ทุกประโยค

## รอบ 2: ร่างบทเมื่อมี Shot description

ลองบน Mac M2 RAM 16 GB เมื่อ 2026-10-31 เพื่อตอบ map: LLM ร่างบทอย่างไรเมื่อมี Shot description ราว 840 รายการ. ใช้ Qwen3.5 9B (D13) กับ mlx-vlm 0.7.11 ใน venv แยกนอก project แล้วลบทิ้งหลังลอง.

### วิธีลอง

- ช่วง 20 นาทีแรกของ `f7jkZXvaB4g`: ตัด Shot ตาม D17 ได้ 192 Shot, บรรยายเฟรมกลางเป็นอังกฤษไม่เกิน 30 คำ
- บท: สไตล์เล่าละคร ราว 350 ตัวอักษร 8 ประโยค, `temperature` 0.7, ปิด thinking, ลองวิธีละ 3 รอบ (seed 1–3)
- **ส่งรวมครั้งเดียว**: Transcript กับ Shot description ทั้งหมดใน prompt เดียว ให้แต่ละประโยคเลือก Shot 2 รายการ
- **สองขั้น**: ขั้นแรกร่างบทจาก Transcript อย่างเดียว ให้แต่ละประโยคอ้างบรรทัด; ขั้นที่สองต่อประโยค ส่งเฉพาะ Shot ที่อยู่ในช่วง ±30 วินาทีรอบบรรทัดที่อ้าง (ราว 9–25 Shot) ให้เลือก 2 รายการ (`temperature` 0)
- ความยาวเต็มเรื่อง: ส่งรวมครั้งเดียวด้วย Transcript ทั้งเรื่องกับ 840 Shot (คำบรรยายจริง 192 รายการวนซ้ำ ใช้วัดเวลาและ memory เท่านั้น)
- ตัดสินว่าภาพตรงไหมจากการดูเฟรมที่เลือกเทียบกับประโยค

### ผล

| | ส่งรวมครั้งเดียว | สองขั้น |
|---|---|---|
| prompt (20 นาที) | 11,561 token | 3,756 token + ราว 400 token ต่อประโยค |
| เวลา (20 นาที, 8 ประโยค) | 110–117 วินาที | 46–89 วินาที |
| memory สูงสุด (20 นาที) | 8.4 GB | 7.5 GB |
| ได้ 8 ประโยคตามสั่ง | 3/3 รอบ | 1/3 รอบ (อีกสองรอบได้ 3 และ 1 ประโยค) |
| ภาพตรงกับประโยค (รอบที่ได้ 8 ประโยค) | ราว 6/8 | ราว 5/8 |
| เต็มเรื่อง: prompt | 61,336 token | ขั้นแรกเท่ารอบ 1 (ราว 26,000 token) |
| เต็มเรื่อง: เวลา | 616 วินาที (อ่าน prompt 105 token/วินาที) | ขั้นแรกราว 263 วินาที (รอบ 1) + ราว 5 วินาทีต่อประโยค |
| เต็มเรื่อง: memory | ค่า default หน่วยความจำ GPU ไม่พอ (`kIOGPUCommandBufferCallbackErrorOutOfMemory`); `prefill_step_size=256` ผ่าน ที่ 10.1 GB (footprint ทั้ง process 12.1 GB) | 9.9 GB (รอบ 1) |
| เต็มเรื่อง: บท | เล่าแค่ 3 นาทีแรก และเลือก Shot เรียงเลข S12–S31 ไม่ดูเนื้อหา | — |

- บรรยายภาพ: 3.2 วินาทีต่อ Shot (192 Shot ใน 608 วินาที), memory 6.4 GB, ราว 25 token ต่อคำบรรยาย. หนังเต็มเรื่อง 840 Shot จึงราว 45 นาที ไม่ใช่ 70 นาทีที่ D17 ประมาณ
- คำบรรยายภาพมีของที่ไม่มีจริงบ้าง (บุหรี่, "เต้นรำในสวน") และ Shot ที่มีเครดิตเปิดเรื่องถูกเลือก
- ทั้งสองวิธีบทยังแต่งเรื่องที่ไม่มีในหนัง (ชื่อ "แจ็ค", วิญญาณ, รถหมดน้ำมัน) และมีอักษรจีนปน (`扫墓`, `来抓`, `現場`)

### สรุป

- ส่งรวมครั้งเดียวใช้ได้กับช่วงสั้น แต่เต็มเรื่องใช้เวลา 10 นาที, เกือบเต็ม RAM 16 GB และบทเสียจนใช้ไม่ได้
- สองขั้นขยายได้ตามความยาวหนัง (ขั้นที่สองเห็นแค่ Shot รอบบรรทัดที่อ้าง) และจับคู่ภาพได้ใกล้กัน แต่ขั้นแรกทำตามจำนวนประโยคได้ไม่เสถียร: ต้องตรวจผลแล้วสั่งใหม่
- ภาษาไทยยังต้องแก้ทุกประโยค (D4) และต้องกรองอักษรจีนออก

## ยังไม่ได้ลอง

- llama-cpp-python กับไฟล์ GGUF (ทางที่รันได้ทั้ง Mac และ Windows) — ลองแค่ MLX ซึ่งรันได้เฉพาะ Mac
- prompt หลายรอบ เช่น สรุปทีละช่วงก่อนแล้วค่อยเขียนบท
- ต้นฉบับภาษาไทยหรือภาษาอื่น
