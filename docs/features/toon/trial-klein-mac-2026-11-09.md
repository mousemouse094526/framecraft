## 1. ต้องแยกขั้นจริง — โหลดพร้อมกันไม่ลง

| ขั้น | เวลา | peak MPS | peak ทั้งระบบ |
|---|---|---|---|
| โหลด text encoder (Qwen3-4B) ขึ้น MPS | 5.4 วิ | 8.06 GB | — |
| encode 17 prompt | 87.6 วิ (5.2 วิ/prompt) | 9.35 GB | 13.71 GB |
| โหลด transformer + vae | รวมในขั้นถัดไป | — | — |
| สร้างภาพ 21 ภาพ | 84.0–286.3 วิ/ภาพ | **14.96 GB** | **14.89 GB** |

- ใช้ `device_map="mps"` ตอน `from_pretrained` — ถ้าโหลดลง CPU แล้ว `.to("mps")` จะมีสำเนาสองชุดพร้อมกัน = swap ทันที
- เก็บ `prompt_embeds` ของ 17 prompt ลงดิสก์ (134 MB) แล้ว **ปล่อย text encoder ก่อนโหลด transformer** — ขั้น GGUF จึงไม่ต้องโหลด encoder ซ้ำเลย
- **peak ทั้งระบบ 14.89 / 17.2 GB** = พอดีขอบเครื่อง ไม่มีที่ให้โปรแกรมอื่นตอน denoise

## 3. GGUF Q8_0 บน MPS ใช้ได้

| | bf16 (transformer ในเครื่อง) | GGUF Q8_0 |
|---|---|---|
| t2i 1 ภาพ | 89.6 วิ · peak **14.96 GB** | 88.9 วิ · peak **10.87 GB** |
| 1 ภาพอ้างอิง | 103.6 วิ · peak 14.96 GB | 98.4 วิ · peak **11.2 GB** |
| ขนาดไฟล์ | 7.75 GB | **4.3 GB** |

- เร็วเท่ากัน แต่ **ประหยัด peak ~4 GB** → เหลือที่ให้ text encoder/แอปอื่นได้จริงบนเครื่อง 16 GB
- ต้องส่ง `config=<โฟลเดอร์ transformer ในเครื่อง>` ให้ `from_single_file` ไม่งั้น diffusers จะไปง้าง `black-forest-labs/FLUX.2-dev` จาก metadata ของไฟล์ GGUF แล้วล้มด้วย `OSError`
- ต้องติดตั้งแพ็กเกจ `gguf>=0.10.0` แยก (diffusers ไม่ดึงมาให้)
- คุณภาพเทียบ bf16: ภาพตัวอย่าง G0/G1 เทียบ A0/C1 — ไม่เห็น noise หรือสีเพี้ยนที่ระดับสายตา

## 4. พฤติกรรมของโมเดล (ตรวจด้วยตา — ตัวอย่างใน [trial-images/](trial-images/))

- ✅ **คงตัวละคร 10 ภาพ** (ref ตัวละคร 1 ภาพ): ทรงหัวกลม ตาจุด ชุดกรมท่า เหมือนเดิมทุกภาพ ไม่มีหน้าบิด ตัวซ้ำ หรือหลุดสไตล์
- ⚠️ **กรอบภาพไม่คงที่** — ตัวละครใหญ่กลางจอบ้าง เล็กจิ๋วบ้าง หันหลังบ้าง ทั้งที่ prompt ต่างกันแค่ฉาก → งานการ์ดต้องมีข้อกำหนดมุม/ระยะในคำสั่งภาพ ไม่ปล่อยลอย
- ✅ **สองตัวในภาพเดียว ไม่ปนหน้า** (ref 2 ภาพ = ตัวละคร 2 คน) ทั้ง 2 ภาพ ตัวละครแยกกันชัด → ตอบคำถาม Open #18 ว่า 2 ตัวต่อการ์ดทำได้
- ⚠️ **character sheet ไม่ได้อย่างที่คิด** — สั่ง "หัวกลม ตาจุด ชุด..., พื้นหลังขาว" ได้ **ภาพ bust ครึ่งตัว** ไม่ใช่แผ่นรวมหน้าตรง/เฉียง/สีหน้า ต้องเปลี่ยนวิธีทำภาพอ้างอิงตัวละคร (ข้อ #4)
- ✅ **ฉากหลังเดี่ยว (ไม่มีคน) สะอาด** → ส่งเป็นภาพอ้างอิงคู่ตัวละครได้ตามแนวข้อ #5
- ✅ **โทนมืด สว่างแค่แหล่งแสง ทำได้** และทำได้ดีกับแสงสีจัด (หลอดฟ้า แสงส้ม ป้ายแดง)
- ⚠️ **ตัวหนังสือในภาพเพี้ยน** — ป้าย EXIT ออกมาเป็น `XΓII` → ยืนยัน D19 (ไม่ให้โมเดลวาดข้อความในภาพ ให้ ffmpeg/Kanit ใส่ทีหลัง)
- ⚠️ prompt ที่ไม่มีประธาน ("round heads, dot eyes") ได้ **หัวกลมยักษ์ลอยเรืองแสง** — คำสั่งภาพต้องมีตัวละครเป็นประธานเสมอ

## 5. บั๊กที่เจอระหว่างทำ (ของสคริปต์ ไม่ใช่ของโมเดล)

1. encode prompt หลายอันโดยไม่ใส่ `torch.no_grad()` → graph ค้าง สะสมถึง **12.6 GB** แล้ว `MPS backend out of memory`
2. ตั้งชื่อ attribute ใน `threading.Thread` subclass ว่า `_stop` → ทับของจริงในตัว `Thread` → `TypeError: 'Event' object is not callable` **หลัง** encode เสร็จ (เสียเวลา 82 วิ)
3. ดาวน์โหลดด้วย `hf download --include` แล้วได้ `transformer/` ที่มีแต่ `config.json` — ต้องตรวจรายการไฟล์ต่อโฟลเดอร์ ไม่เชื่อ exit code ของตัวโหลด

## 7. ข้อจำกัดของการลองนี้

- ทดสอบที่ **1024×576 เท่านั้น** ยังไม่ลอง 1024×1024 (token ต่อภาพสูงกว่ามาก)
- ใช้ 4 steps / prompt เดียวต่อภาพ ไม่ได้วัดความต่างของ seed
- ไม่ได้ลองฝึก LoRA ตัวละคร (นอกขอบเขตรอบแรกตาม D6)
- GGUF ที่ลองเป็น Q8_0 ยังไม่ลอง Q6_K / Q4_K_M (จะเหลือ memory น้อยลงอีก แต่คุณภาพต้องดูใหม่)
- ไม่ได้ลอง fp16 (Mac ไม่จำเป็น) และไม่ได้วัดบน RTX (คนละเครื่อง ตาม ADR-0025)
