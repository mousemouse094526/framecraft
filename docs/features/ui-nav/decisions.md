# Decisions: ui-nav

## D1: เมนูหลักมี 5 หัวข้อใหญ่ ติดตั้ง · สปอย · การ์ตูนเล่า · สอนกลอง · แกะเพลง และคลังย้ายไปส่วน "คลัง" ในเมนู

**Chosen:** แถบ tab 8 รายการกับกลุ่ม "เตรียมของ"/"ทำคลิป" ถูกแทนด้วยเมนูหลักเดียว: หัวข้อใหญ่ 5 หัวข้อตามลำดับนี้ แล้วตามด้วยส่วน "คลัง" (D2). หัวข้อใหญ่คืองานที่ทำคลิปหรือเตรียมเครื่อง ไม่ใช่คลัง.

**Why:** เจ้าของบอกว่า "มันดูแปลกๆ ที่ต้องเข้าไปลึกมาก" อยากได้ hamburger menu ที่ "หัวข้อใหญ่ยังอยู่" และ "คลังเพลง คลังคลิปที่ไปอยู่ใน hamburger menu แล้ว". แอปทั่วไปจำกัด primary nav ไว้ 5–7 รายการ ที่เหลือเป็นรายการรอง ([app shell](https://ui-syntax.com/collections/app-shell-layouts)).

**Rejected:**
- คง 8 tab แล้วเพิ่มเมนูย่อยใต้ tab — ยังเป็น tab → ขั้น → รายการ สามชั้น ซึ่งเป็นปัญหาที่เจ้าของบอก
- ให้ขั้นของแต่ละหัวข้อเป็นหัวข้อใหญ่แทน (เจ้าของเปิดทางนี้ไว้) — ได้ 10+ รายการระดับบน เกิน 5–7 และเสียกลุ่มของงาน

**Details:**
- supersedes sound-library D2 (ลำดับแถบ 6/8 รายการ) และ sound-library D3 (กลุ่ม "เตรียมของ"/"ทำคลิป" บนแถบ)
- ลำดับหัวข้อตามลำดับ tab เดิมของแต่ละงาน ติดตั้งยังเป็นหน้าแรกของ hash ว่าง (spoil-maker D53)

**Sources:** [App shell layouts](https://ui-syntax.com/collections/app-shell-layouts)

**From:** interview · **Status:** changed by D12

## D2: ส่วน "คลัง" อยู่ท้ายเมนู แต่ละคลังมีที่เดียว พร้อมบรรทัด "ใช้กับ …"

**Chosen:** ท้ายเมนูมีส่วน "คลัง" 4 รายการ: คลังคลิป (`#/clips`) · คลังความรู้ (`#/stories`) · คลังเสียง (`#/sounds`) · เสียงที่บันทึก (`#/spoil/voices`). ใต้ชื่อแต่ละรายการมีบรรทัดเล็ก "ใช้กับ {หัวข้อ}" ตามที่โค้ดใช้จริง.

**Why:** คลังเสียงกับเสียงที่บันทึกใช้ทั้งสปอยและการ์ตูนเล่า (sound-library D1, `SeriesForm` ลิงก์ `#/spoil/voices`); วางใต้หัวข้อจะต้องซ้ำสองที่ แล้ว `aria-current` ไม่รู้ว่าควรอยู่ที่ไหน. บรรทัด "ใช้กับ" ยังบอกว่าคลังไหนเป็นของงานไหนตามที่ brief ขอ.

**Rejected:**
- วางคลังใต้หัวข้อที่ใช้มัน (การอ่าน brief ข้อ 3) — คลังเสียงกับเสียงที่บันทึกซ้ำสองที่ อยู่ใน Open Questions ถ้าเจ้าของอยากได้แบบนี้
- ไม่ใส่เสียงที่บันทึกในเมนู — วันนี้ไปถึงได้จากปุ่มในขั้น 1 ของสปอยกับฟอร์มชุดเท่านั้น ลึกกว่า 2 คลิก

**Details:**
- การใช้งานจริงในโค้ด: คลังคลิป ← สปอย (`ClipPicker`); คลังความรู้ ← สปอย (`StoryPicker`); คลังเสียง ← สปอย (`BackgroundSound`) และการ์ตูนเล่า (`SeriesList`, `StorylineView`); เสียงที่บันทึก ← สปอย (`SetupSettings`) และการ์ตูนเล่า (`SeriesForm`)
- ชื่อ tab "คลิป" เปลี่ยนเป็น "คลังคลิป" ในเมนู ส่วนหน้า `#/clips` เหมือนเดิม
- "คลังเพลง" ในข้อความเจ้าของอ่านเป็นคลังเสียง: glossary ห้ามใช้ "คลังเพลง" แทนคลังเสียง (`CONTEXT.md` › คลังเสียง) และแกะเพลงยังเป็นหัวข้อใหญ่ (D1)

**From:** interview · **Status:** changed by nav-ia D2

## D3: ขั้นและหน้าหลักของแต่ละหัวข้ออยู่ในเมนูเลย ทุกส่วนเปิดตลอด

**Chosen:** ใต้แต่ละหัวข้อมีรายการที่กดแล้วไปหน้านั้นทันที:

| หัวข้อ | รายการ |
|---|---|
| ติดตั้ง | หัวข้อเป็นลิงก์ `#/setup` เอง ไม่มีรายการ |
| สปอย | 1 เลือกคลิป `#/spoil` · 2 ตรวจแก้บท `#/spoil/review` · 3 ผล render `#/spoil/renders` |
| การ์ตูนเล่า | ชุดทั้งหมด `#/toon` · สร้างชุดใหม่ `#/toon/new` · ล่าสุด (D5) |
| สอนกลอง | บทเรียนทั้งหมด `#/drums` · ล่าสุด (D5) |
| แกะเพลง | เพลงทั้งหมด `#/songs` · ล่าสุด (D5) |

**Why:** เจ้าของอยากให้ "step ที่อยู่ในหัวข้อแต่ละอันก็มีอยู่" ในเมนู; ทุกปลายทางที่เปิดบ่อยต้องถึงใน ≤ 2 คลิกจากหน้าใดก็ได้ (spec › Expected Outcome). ส่วนที่ยุบได้เพิ่มคลิกหนึ่งครั้งจึงไม่ใช้.

**Rejected:**
- ส่วนของแต่ละหัวข้อยุบ/ขยายได้ — คลิกที่สามก่อนถึงขั้น; เมนูมีไม่เกินราว 25 บรรทัดซึ่งอยู่ในจอเดียวที่ 768px สูง
- หัวข้อ (สปอย, การ์ตูนเล่า, …) เป็นลิงก์ด้วย — ซ้ำกับรายการแรก (`#/spoil` = เลือกคลิป, `#/toon` = ชุดทั้งหมด)
- ใส่หน้าย่อยของชุดที่เปิดอยู่ (EP, ตัวละครและฉากหลัง, ตั้งค่า) ในเมนู — หน้าของชุดมีลิงก์ของมันแล้ว และ "ล่าสุด" ทำให้กลับเข้าชุดได้ใน 2 คลิก

**Details:**
- หัวข้อที่ไม่ใช่ลิงก์เป็นหัวของกลุ่ม (`role="group"` กับ `aria-labelledby`) แบบเมนูจอแคบเดิม (sound-library D16)
- ตัวบอกขั้นในหน้าสปอยคงอยู่ตามเดิม เพราะบอกสถานะงานของแต่ละขั้น (spoil-maker D68)

**From:** interview · **Status:** superseded by nav-ia D5

## D4: เมนูเดียว: จอ ≥1024px เป็น sidebar ตรึงซ้ายยุบได้ จอแคบเป็น drawer จากปุ่ม ☰

**Chosen:** เมนูหลักเป็น `<nav>` ตัวเดียวชื่อ "เมนูหลัก". จอตั้งแต่ 1024px เป็น sidebar ตรึงซ้ายกว้าง 256px เปิดอยู่ก่อน. ต่ำกว่า 1024px ซ่อนอยู่และเปิดเป็น drawer ทับหน้าจากซ้าย. ปุ่ม ☰ ที่หัวทุกหน้าเปิด/ปิดเมนูทั้งสองแบบ; จอกว้างจำว่ายุบไว้หรือไม่ในเบราว์เซอร์.

**Why:** hamburger ที่ซ่อนเมนูบนเดสก์ท็อปทำให้คนค้นพบ feature น้อยลง ([NN/g](https://www.nngroup.com/articles/hamburger-menus/)); hamburger เหมาะกับจอแคบที่ไม่มีที่. หัวข้อและขั้นชุดเดียวกันทั้งสองแบบ เพราะเป็น element เดียวกัน.

**Rejected:**
- hamburger อย่างเดียวทุกจอ (การอ่านคำเจ้าของตรงตัว) — ซ่อนเมนูบนจอที่มีที่เหลือ
- sidebar ยุบเป็นแถบไอคอน — แอปไม่มีไอคอนของแต่ละงาน ต้องออกแบบไอคอน 9+ ตัวก่อน
- drawer เป็น modal ที่กักโฟกัส (`<dialog>`) — ต้องแยกเป็นสอง element สำหรับสองจอ; ใช้ disclosure แบบเดิมแทน (sound-library D16)

**Details:**
- supersedes sound-library D16 (ปุ่มเมนูจอแคบ "เมนู tab: {หน้า}")
- ปุ่ม ☰ เป็น disclosure: `aria-expanded` กับ `aria-controls` ชี้ "เมนูหลัก"; ชื่อ "เมนู: {หัวข้อที่เปิด}"
- drawer ปิดเมื่อเลือกรายการใดก็ได้, กด `Esc` (โฟกัสกลับปุ่ม), กดนอกเมนู หรือกดปุ่มอีกครั้ง (`useDismiss` เดิม); sidebar บนจอกว้างไม่ปิดเมื่อเลือกรายการ
- จุดแบ่ง 1024px คือ `lg` ของ Tailwind ใช้ `useIsDesktop` ของ spoil-maker ที่ย้ายไป `lib/` เพราะมีผู้ใช้สองที่
- ค่า "ยุบ" เก็บใน `localStorage` key `framecraft.nav.collapsed`; อ่านไม่ได้ = เปิด

**Sources:** [Hamburger menus and hidden navigation hurt UX metrics (NN/g)](https://www.nngroup.com/articles/hamburger-menus/)

**From:** interview · **Status:** changed by D11, D14

## D5: "ล่าสุด" ในเมนู: ของที่เปิดล่าสุดไม่เกิน 3 รายการต่อหัวข้อ

**Chosen:** ใต้การ์ตูนเล่า สอนกลอง และแกะเพลง มีรายการ "ล่าสุด" ไม่เกิน 3 รายการต่อหัวข้อ ใหม่สุดก่อน: ชุดหรือ EP, บทเรียนกลอง, เพลง ที่เปิดล่าสุดในเบราว์เซอร์นี้. กดแล้วถึงหน้านั้นใน 2 คลิกจากหน้าใดก็ได้.

**Why:** ปลายทางที่ลึกที่สุดวันนี้คือของชิ้นเดียว (EP: tab → ชุด → EP สามคลิก; reel ของเพลง: tab → เพลง → reel). เมนูใส่ทุกชุดไม่ได้ แต่ของที่ทำค้างอยู่คือที่ที่ผู้ใช้กลับไปบ่อยที่สุด.

**Rejected:**
- ไม่มีล่าสุด เมนูมีแค่หน้าคงที่ — การ์ตูนเล่า สอนกลอง และแกะเพลงยังลึก 3 คลิกเหมือนเดิม ไม่ตอบปัญหาหลัก
- รายการทุกชุด/ทุกเพลงในเมนู — ยาวไม่จำกัด และต้องโหลด API ทุกหน้า
- เก็บล่าสุดที่ backend — เป็นความสะดวกของเบราว์เซอร์เดียว ไม่ต้องมี API ใหม่

**Details:**
- เขียนเมื่อหน้าของชิ้นนั้นโหลดข้อมูลสำเร็จ: ชุด (`#/toon/series/{sid}`), EP (`#/toon/eps/{eid}`), บทเรียน (`#/drums/{id}`), เพลง (`#/songs/{id}`); ชื่อคือชื่อที่หน้านั้นแสดงเป็นหัว
- หน้าย่อย (`/cast`, `/settings`, `/plot`, `/render`, `/renders`, `/cover`) เขียนชิ้นแม่ของมัน ไม่เขียนตัวเอง
- เปิดซ้ำย้ายขึ้นบนสุดและอัปเดตชื่อ; ไม่ซ้ำ hash; เกิน 3 ตัดตัวเก่าสุด
- หน้าที่ได้ `not_found` หรือผู้ใช้ลบชิ้นนั้นในแอป ลบรายการนั้นออก
- เก็บใน `localStorage` key `framecraft.nav.recent`; อ่านหรือเขียนไม่ได้ = ไม่มีล่าสุด หน้าอื่นทำงานปกติ

**From:** interview · **Status:** changed by D11; changed by nav-ia D18

## D6: hash ทุกตัวเหมือนเดิม; รายการที่เปิดอยู่หาจาก hash ด้วย prefix ที่ยาวที่สุด

**Chosen:** ไม่มี hash ใดเปลี่ยนชื่อหรือหายไป; `tabOf` และ prop `tab` ของ `PageLayout` เหมือนเดิม จึงไม่มีหน้าใดต้องแก้เพื่อเมนู. รายการในเมนูที่ได้ `aria-current="page"` คือรายการที่ hash ปัจจุบันเท่ากับ hash ของมัน หรือขึ้นต้นด้วย hash ของมันตามด้วย `/` หรือ `?`; มีหลายรายการ → ตัวที่ hash ยาวที่สุด.

**Why:** brief ข้อ 6: deep link เดิมต้องไม่พัง และทุกอย่างที่ทำได้วันนี้ต้องทำได้เหมือนเดิม.

**Rejected:**
- ให้แต่ละหน้าบอกเมนูว่าตัวเองคือรายการไหน — ต้องแก้ 20+ หน้า และลืมได้

**Details:**
- ตัวอย่าง: `#/spoil/xyz` → เลือกคลิป (ตรงกับ `stepOf`); `#/toon/series/a/cast` → ล่าสุดของชุด a ถ้ามี ไม่มี → ชุดทั้งหมด; `#/songs/s1/cover` → ล่าสุดของเพลง s1 หรือเพลงทั้งหมด; `#/sounds?back=#/toon` → คลังเสียง; hash ว่างหรือไม่รู้จัก → ติดตั้ง
- หัวข้อที่ `tabOf` ให้ได้ตัวเน้น (หัวกลุ่มสี brand) แม้ไม่มีรายการใดตรง
- หัวของทุกหน้าแสดงตำแหน่ง: "{หัวข้อ}" ตามด้วย " / {รายการ}" เมื่อมีรายการที่ตรง; `<h1>` ที่ซ่อนยังเป็นชื่อหัวข้อตามเดิม
- leave guard (`useLeaveGuard`) ทำงานเหมือนเดิมเพราะทุกรายการเป็นลิงก์ `#/…` ธรรมดา

**From:** interview · **Status:** changed by D11; changed by nav-ia D1, D9, D16

## D7: สร้างตาม ui-prompt.md กับ design system เดิม ไม่รอ Figma

**Chosen:** เมนู (sidebar กับ drawer) และหัวหน้าใหม่สร้างตาม [ui-prompt.md](ui-prompt.md) กับ token ใน `index.css` เลย ไม่มีแบบใน Figma ก่อน. แบบใน Figma ภายหลังเป็น change request.

**Why:** เจ้าของบอก "ไม่จำเป็นต้องออกแบบฟิกมาก่อน แตก branch แล้วทำการ redesign ให้หน่อย"; ทางเดียวกับ drum-notes D28.

**Rejected:**
- ออกแบบใน Figma ก่อนสร้าง — เจ้าของบอกว่าไม่ต้อง

**From:** interview · **Status:** active

## D8: test ที่ผูกกับหน้าตาแถบ tab เดิมเขียนใหม่ตั้งใจ

**Chosen:** test ที่หา `navigation` ชื่อ "แถบ tab" หรือ "เมนู tab" หรือลำดับ 8 tab เขียนใหม่ให้หา "เมนูหลัก" กับรายการใหม่: `App.test.tsx` (ส่วน tab bar, tab groups, tab menu), `SoundsPage.test.tsx` และ `StoryEditor.test.tsx` (คลิกลิงก์ในแถบ). test ที่ตรวจ hash, หน้า, back button และ leave guard คงพฤติกรรมเดิม เปลี่ยนแค่ที่หาลิงก์.

**Why:** แถบ tab กับกลุ่มของมันไม่มีแล้ว (D1, D4); ชื่อ "แถบ tab" บนเมนูที่ไม่ใช่แถบจะผิดสำหรับ screen reader.

**Rejected:**
- คงชื่อ "แถบ tab" ไว้ให้ test เดิมผ่าน — ชื่อผิดกับสิ่งที่เป็น และ test ลำดับ/กลุ่มก็ต้องแก้อยู่ดี

**From:** interview · **Status:** active

## D9: seam เดียวคือ `App` ที่ render ใน jsdom

**Chosen:** ทุกพฤติกรรมของเมนูพิสูจน์ผ่าน `App` กับ Testing Library แบบ `App.test.tsx` เดิม; ล่าสุดพิสูจน์ผ่านหน้าที่เขียนมัน (render หน้านั้นด้วย fetch ปลอม แล้วดูเมนู).

**Why:** เมนูเป็น UI ล้วน ไม่มี API ใหม่; `App.test.tsx` เป็น seam ที่มีอยู่และสูงสุดที่ใช้ได้. project ไม่มีเครื่องมือ e2e แยก: test ของ Testing Library คือ e2e ของ project (ป้าย `(e2e)` ใน `App.test.tsx`).

**Rejected:**
- test ของ `nav.ts` แยกทีละฟังก์ชันเป็น seam หลัก — ใช้ได้เป็น test เสริมของกฎ prefix แต่พฤติกรรมที่ผู้ใช้เห็นอยู่ที่ `App`

**From:** interview · **Status:** active

## D10: กฎที่ red team เพิ่ม

**Chosen:** bundle ของกฎโฟกัส ความทนของล่าสุด และการถอยกลับ จาก red team.

**Details:**

**Chosen:** เมนูหลักเรียงเป็นหมวด แต่ละหมวดมีหัวหมวดแล้วตามด้วยหัวข้อหรือรายการของมัน:

## D13: เมนูมีเฉพาะทางที่ได้ reel หรือของที่ reel ใช้; ไม่แน่ใจ = เก็บไว้

**Chosen:** รายการในเมนูหลักต้องผ่านข้อใดข้อหนึ่ง: (ก) กดแล้วเดินต่อจนได้ไฟล์คลิปแนวตั้งออกมา, (ข) เป็นของที่หน้าทำ reel อ่านไปใช้ (คลัง), หรือ (ค) ตั้งค่าเครื่องให้ทำ reel ได้. รายการที่ใช้สอนหรือสร้างบทเรียนโดยไม่ได้คลิป ไม่อยู่ในเมนู. รายการที่ไม่แน่ใจคงอยู่และเป็น Open Question ให้เจ้าของตัดสิน.

**Rejected:**
- เอาสอนกลองออกจากเมนูเพราะเป็น "บทเรียน" — มันได้ mp4 แนวตั้งพร้อม .srt จริง (`backend/video_gen/render.py`) จึงเข้าข้อ (ก); ขัดกันระหว่าง "บทเรียนไม่เอา" กับ "ทำ reels ได้เอาไว้" = ไม่แน่ใจ → เก็บไว้ตามคำเจ้าของ
- ซ่อนส่วน "สร้างบทเรียน" กับ "บทเรียนจากเพลงนี้" ในหน้าเพลงในงานนี้ — เป็นหน้าของ drum-notes ไม่ใช่เมนู และแตะ ADR-0047; เป็น change request แยก (Open Questions)

**Details:**
- ผลตรวจรายการในเมนูวันนี้ ทีละรายการ (ดูโค้ด 2026-11-17):

| รายการ | ข้อ | ผล |

| การ์ตูนเล่า: ชุดทั้งหมด · สร้างชุดใหม่ · ล่าสุด | ก | อยู่ |
| แกะเพลง: เพลงทั้งหมด · ล่าสุด | ก (หน้าเพลงมี "ทำ reel cover" → `#/songs/{id}/cover`) | อยู่ |

## D14: แบรนด์และปุ่มยุบ/ปิดอยู่หัวเมนู; หัวหน้าเหลือ ☰ (เมื่อเมนูซ่อน) หัวข้อหน้า และ action

**Chosen:** หัวของเมนูหลัก (sidebar และ drawer) เป็นแถวแรกในเมนู: wordmark "framecraft" ซ้าย ปุ่มของเมนูขวา — sidebar ≥1280px เป็นปุ่ม "ยุบเมนู" (ไอคอนแผงซ้าย), drawer เป็นปุ่ม "ปิดเมนู" (ไอคอน ×). หัวหน้า (`<header>` ของคอนเทนต์) เหลือ `[☰] {หัวข้อหน้า} … {action}`: ปุ่ม ☰ "เมนู: {ข้อความตำแหน่ง}" อยู่ในหัวหน้าเมื่อเมนูซ่อนได้: จอ <1280px ทุกเวลา (drawer เปิดหรือปิด), จอ ≥1280px เมื่อยุบเท่านั้น และเป็นปุ่มไม่มีขอบชิดหัวข้อหน้า; หัวข้อหน้าคือ `<h1>` ที่เห็นได้ แสดงข้อความตำแหน่ง (D11) ส่วนหัวข้อเป็นสี `muted-foreground` ส่วนรายการเป็น `foreground` ตัวหนา 18px.

**Why:** เจ้าของ (change request 2026-11-19): "ปรับ ui ตัว framecraft ตรงหัวกับhamberger icon มันดูไม่เห็นเกียวของกันเลย มันดูแยกกัยแล้วดูไม่สวยเลยปรับหน่อย". วันนี้ ☰ เป็นกล่องมีขอบ 44px วางชิด wordmark 26px คนละน้ำหนักคนละความหมาย; บนจอ ≥1280px ปุ่มยุบ sidebar ลอยอยู่ในหัวคอนเทนต์ไกลจาก sidebar ที่มันควบคุม; ข้อความตำแหน่งเป็นบรรทัดเทาเล็กที่ไม่ทำหน้าที่หัวข้อ. แบรนด์กับปุ่มยุบเป็นของเมนู จึงย้ายไปอยู่กับเมนู; หัวคอนเทนต์เป็นของหน้า จึงเหลือหัวข้อหน้ากับ action ของหน้า.

**Rejected:**
- คง ☰ + wordmark ในหัวคอนเทนต์ แค่ทำปุ่มไม่มีขอบและ wordmark เล็กลง — ปุ่มยุบยังไกลจาก sidebar ที่มันควบคุม และหัวข้อหน้ายังเป็นบรรทัดรอง
- ปุ่มเดียวที่ย้ายตำแหน่งตามสถานะ (render ที่ใหม่ทุกครั้ง) — remount ทำโฟกัสหาย ต้องจัดการโฟกัสอยู่ดี; สองปุ่มที่ชื่อบอกหน้าที่ตรงกว่า
- sidebar ยุบเป็นแถบไอคอนที่มีแบรนด์ — แอปไม่มีไอคอนของแต่ละงาน (D4)
- wordmark ในหัวคอนเทนต์ตอนเมนูซ่อน — กลับไปเป็นของสองชิ้นวางข้างกันที่เจ้าของไม่ชอบ; แบรนด์เห็นเมื่อเปิดเมนู (Open Question 7)

**Details:**
- changes D4: ปุ่ม ☰ ที่หัวหน้าไม่ได้อยู่ทุกหน้าทุกจอแล้ว — ☰ คงเป็น disclosure ตัวเดียว (`aria-expanded` = เมนูเห็นอยู่ไหม `aria-controls` = เมนูหลัก, ชื่อ "เมนู: {ข้อความตำแหน่ง}" ตาม D11 เดิม); ปุ่มในหัวเมนูเป็นปุ่มเดียวที่ชื่อ ไอคอน และขนาดตาม `pinned` ("ยุบเมนู" / "ปิดเมนู") เป็นปุ่มธรรมดาไม่มี `aria-expanded`/`aria-controls` เพราะมันหายไปพร้อมเมนู; หัวเมนูอยู่ใน `<nav>` เพราะ `<nav>` คือ panel ของ `useDismiss` (กดในนั้นไม่นับเป็นกดนอก); ค่ายุบ `framecraft.nav.collapsed`, จุดตรึง 1280px และ drawer ปิดเมื่อเลือก `Esc` กดนอก คงเดิม
- changes D10 (ยุบ sidebar ขณะโฟกัสอยู่ในเมนู): กด "ยุบเมนู" → โฟกัสไป ☰ ในหัวหน้า; กด ☰ บนจอ ≥1280px → sidebar ขยายแล้วโฟกัสไป "ยุบเมนู" — ย้ายหลัง render (flag รอโฟกัสที่ effect ของค่ายุบใช้) เพราะปุ่มปลายทางยังไม่มีตอนกด; เลือกรายการบน sidebar ยังไม่ย้ายโฟกัสเหมือนเดิม
- ข้าม 1280px ขณะเปิดหน้า: ถ้าโฟกัสตกที่ `<body>` (ปุ่มที่มีโฟกัสหายไป) หรืออยู่ในเมนูที่เพิ่งซ่อน → โฟกัสไปตัวที่คุมเมนูตอนนี้: "ยุบเมนู" ถ้า sidebar เห็น, ☰ ถ้าเมนูซ่อน; ไม่ทำตอน render แรก
- กด "ปิดเมนู" ใน drawer → ปิดแล้วโฟกัสกลับ ☰ เหมือน `Esc`; ☰ ยังสลับได้ (กดซ้ำปิด) แบบเดิม; กฎโฟกัสอื่นของ drawer (เปิดแล้วไปรายการที่เปิดอยู่ เลือกแล้วกลับ ☰ เนื้อหาและ action `inert`) คงเดิม (D10)
- ข้ามจุดแบ่งระหว่างเปิดหน้า: ☰ โผล่หรือหายตามกฎข้างบน; drawer ที่เปิดอยู่ปิดเหมือนเดิม (D4)
- ☰ ข้างหลัง drawer ไม่ `inert` (`useDismiss` ย้ายโฟกัสกลับมันตอน `Esc` ก่อน render ใหม่) จึง Tab จากรายการสุดท้ายไปถึงมันได้ — ยอมรับ: กดแล้วปิด drawer ตามที่คาด
- screen reader อ่านตำแหน่งสองครั้ง (ชื่อ ☰ กับ `<h1>`) — ยอมรับ: ชื่อ ☰ เป็นสัญญา test ของ D11
- `<h1>` ที่เคยเป็น `sr-only` ชื่อหัวข้อใหญ่ (`tabLabel`) เปลี่ยนเป็นหัวข้อที่เห็นได้ ข้อความ = ข้อความตำแหน่ง (D11) ตัดด้วย … บรรทัดเดียว; หัว `<h2>` ของหน้า (20px) ใหญ่กว่า `<h1>` 18px โดยตั้งใจ: `<h1>` บอกตำแหน่งในแอป `<h2>` เป็นเนื้อหาของหน้า ตาไม่ต้องอ่านตำแหน่งก่อน; `tabLabel` ยังใช้ใน `nav.ts` และ `sounds.ts`
- จอแคบ: ☰ กับหัวข้อหน้าอยู่แถวเดียวกับ action; ☰ เป็นปุ่ม 44px ไม่มีขอบ ไอคอนชิดขอบคอนเทนต์ (ขยับซ้าย 12px) ให้อ่านเป็นหน่วยเดียวกับหัวข้อ
- หัวเมนูสูง 44px wordmark 22px; ปุ่มในหัวเมนู 36px บน sidebar, 44px ใน drawer (touch target D4)
- ไอคอนใหม่สองตัวแบบเดียวกับ `menu.svg` (16px เส้น 1.5 สี `muted-foreground`): `sidebar.svg` (แผงซ้าย) และ `close.svg` (×); `x.svg` เดิมเส้นหนาสีเข้มกว่า จึงไม่ใช้ในหัวเมนู
- ถอยกลับ: revert commit ของ ticket 04 (หรือ merge commit ของ PR) รวม test ที่เขียนใหม่และ `sidebar.svg` คืนหัวของ PR #20; ไม่มี storage key หรือ hash ใหม่ (D10)
- หัวเมนู sticky บนสุดของเมนูขณะเลื่อน: drawer ที่เปิดบนติดตั้ง (ท้ายเมนู) ยังเห็นแบรนด์และ "ปิดเมนู"

## D15: รายการเมนู "เสียงที่บันทึก" เรียก "เสียงพากย์" บนจอทั้งแอป

**Chosen:** คำบนจอของ Saved voice เป็น "เสียงพากย์" ทุกที่: รายการในเมนูหลัก (หมวดคลัง) ข้อความตำแหน่งในหัวหน้า ("คลัง / เสียงพากย์") หัว `<h2>` และแผงในหน้า Saved voice ช่องเลือกเสียงในขั้น 1 ของสปอย (`SetupSettings`: ป้าย, "ยังไม่มีเสียงพากย์", ลิงก์ "สร้างเสียงพากย์") — เดิม "เสียงบรรยาย" — และข้อความ error `voice_not_found` ของการ์ตูนเล่า 3 ที่ ("… เลือกเสียงพากย์"). hash `#/spoil/voices` ชื่อในโค้ด (`SavedVoicePage`, Saved voice) และรหัส error ไม่เปลี่ยน.

**Why:** เจ้าของ (2026-11-19): "เปลี่ยนชื่อรายการเมนู เสียงที่บันทึก เป็น เสียงพากย์ ให้ตรงกันทั้งแอป … เปลี่ยนแค่คำบนจอ ห้ามแตะ hash #/spoil/voices และชื่อในโค้ด".

**Rejected:**
- เปลี่ยน hash เป็น `#/voices` หรือ rename ในโค้ด — เจ้าของห้าม; bookmark เดิมต้องเปิดได้ (D6)

**Details:**
- changes D2 และ D12: ชื่อรายการที่สี่ของหมวดคลังเป็น "เสียงพากย์"; ตำแหน่ง "ใช้กับ สปอย, การ์ตูนเล่า" และกฎของ ADR-0063 เหมือนเดิม
- ที่อื่นที่ยังเขียน "Saved voice" บนจอ (ฟอร์มชุดของการ์ตูนเล่า `SeriesForm`, กล่องยืนยันลบชุด `SeriesList`) เปลี่ยนเป็น "เสียงพากย์" แล้วตามคำสั่งเจ้าของรอบสอง (2026-11-19) และลิงก์ที่เคยเขียนว่า "tab สปอย" แก้เป็น "สปอย" เพราะแอปไม่มีแถบ tab แล้ว
- glossary: `CONTEXT.md` › Saved voice บอกคำบนจอ และเลี่ยง "เสียงที่บันทึก"
- ถอยกลับ: revert commit นี้; ไม่มี storage หรือ hash ใหม่
