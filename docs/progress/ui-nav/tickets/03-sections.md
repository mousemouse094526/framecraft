# 03: เมนูเป็น 4 หมวด เฉพาะทางที่ได้ reel

**What to build:** เมนูหลักแบ่งเป็น 4 หมวดที่มีหัว: เล่าเรื่อง (สปอย, การ์ตูนเล่า) · ดนตรี (แกะเพลง, สอนกลอง) · คลัง (4 คลังพร้อม "ใช้กับ …") · ตั้งค่า (ติดตั้ง). ทุกรายการในเมนูผ่านกฎ reel ของ D13; สอนกลองยังอยู่จนเจ้าของตัดสิน. hash หน้าที่เปิด ข้อความตำแหน่ง ล่าสุด และปุ่ม ☰ ทำงานเหมือนเดิม.

**Blocked by:** None (can start immediately)

**Covers:**
- Decisions: D12, D13
- Screens: เมนูหลักและหัวหน้า (ทุกหน้า)
- Seams: 1
- User stories: 7

**Status:** done

## Acceptance criteria

### หมวด

- hash ว่าง → "เมนูหลัก" มีหมวด เล่าเรื่อง ดนตรี คลัง ตั้งค่า ตามลำดับ; ใต้เล่าเรื่องมีกลุ่ม สปอย การ์ตูนเล่า; ใต้ดนตรีมีกลุ่ม แกะเพลง สอนกลอง; ใต้คลังมี 4 รายการพร้อม "ใช้กับ …" ตรงตัวเดิม; ใต้ตั้งค่ามีลิงก์ ติดตั้ง (e2e)
- ลำดับลิงก์ทั้งเมนู: เลือกคลิป ตรวจแก้บท ผล render ชุดทั้งหมด สร้างชุดใหม่ เพลงทั้งหมด บทเรียนทั้งหมด คลังคลิป คลังความรู้ คลังเสียง เสียงที่บันทึก ติดตั้ง (e2e)
- หัวหมวดไม่ใช่ลิงก์และไม่ได้ `aria-current`; หัวข้อที่เปิดยังได้ `aria-current="true"` (e2e)

### ไม่พังของเดิม

- ทุกแถวของ spec › Implementation › Hash ยังเน้นรายการ หัวข้อ และข้อความตำแหน่งเดิม (e2e)
- ล่าสุดยังขึ้นใต้หัวข้อของมัน (การ์ตูนเล่า แกะเพลง สอนกลอง) (e2e)
- drawer ที่เปิดบน hash ที่ไม่มีรายการตรง ยังโฟกัสรายการแรกของเมนู (e2e)
- `uv run pytest`, `typecheck`, `test`, `build` ผ่าน
