# 13: คลังเสียงพื้นที่ไม่หายเมื่อ sounds.json เสีย

**What to build:** `sounds.json` ที่เสียหรือหายไม่ทำให้คลังเสียงพื้นหายอีก: ตอน start แอปตรวจคลังกับไฟล์ m4a ที่มีอยู่ เก็บไฟล์เสียไว้ และกู้เสียงทุกตัวกลับมาโดย id เดิม (ชื่อเป็น id) ช่วงของ EP ยังชี้เสียงถูก. import และลบเสียงไม่ทิ้งรายการซ้ำหรือไฟล์กำพร้าแม้ crash กลางทาง. ค่าคู่ตัวละคร/ฉากหลังและจำนวนสูงสุดของพล็อตเขียนที่เดียว.

**Blocked by:** None (can start immediately)

**Covers:**
- Decisions: D70
- Seams: 1 (คลังเสียงพื้น ข้อ `sounds.json` เสีย)
- Blocked: #30; smell ค้างจาก feature review รอบห้า (`kind` คู่ characters/backgrounds และ `PLOT_*_MAX` สามที่)

**Status:** done

## Acceptance criteria

### ตรวจคลังตอน start

- `sounds.json` เป็นข้อความเสีย ขณะมี m4a สองไฟล์ → start ใหม่ → รายการเสียงมีสองตัว ชื่อเป็น id, ไฟล์เดิมอยู่เป็น `sounds.json.bad-*`
- `sounds.json` เป็น `version` อื่น → เก็บเป็น `.bad-*` และกู้แบบเดียวกัน
- รายการหนึ่งตัวรูปผิด หรือ id ไม่ตรงรูปแบบ → start ใหม่ → รายการนั้นหาย รายการอื่นชื่อเดิม; m4a ของมันกลับมาชื่อเป็น id เมื่อชื่อไฟล์ตรงรูปแบบ
- รายการที่ไม่มีไฟล์ m4a → หายหลัง start ใหม่
- m4a ที่ ffmpeg อ่านไม่ได้หรือเกิน 10 วินาที → อยู่ในคลัง ความยาว `0`
- ช่วงของ EP ที่ใช้เสียงที่กู้มา → render ไม่บอกว่าเสียงเปลี่ยน
- คลังที่ตรงกับไฟล์อยู่แล้ว → start ใหม่ไม่เขียน `sounds.json`

### ระหว่างทำงาน

- ไม่มี `sounds.json` → import หนึ่งไฟล์ → หนึ่งเสียง ไม่มี id ซ้ำ
- `sounds.json` ถูกเขียนเป็นข้อความเสียขณะแอปเปิด แล้ว import → คลังมีเสียงเดิมทุกตัวและเสียงใหม่ (ความยาวของเสียงที่กู้เป็น `0` จน start ใหม่)
- เขียน `sounds.json` ที่กู้ไม่สำเร็จ → การอ่านคลังไม่ error คืนรายการที่กู้ได้
- crash หลังวาง m4a ก่อนเขียน `sounds.json` → start ใหม่ เสียงนั้นอยู่ในคลัง
- ลบเสียงแล้ว crash ก่อนเขียน `sounds.json` → start ใหม่ เสียงนั้นไม่กลับมา

### ค่าที่เขียนที่เดียว

- คู่ characters/backgrounds และจำนวนตัวละคร/ฉากหลังสูงสุดของพล็อต มาจากที่เดียวที่ `episodes`, `writer` และ `cards` อ่าน; พฤติกรรมเดิมทุกอย่าง
- test ที่มีอยู่ยังผ่าน จำนวนไม่ลด; `uv run pytest` และ check ของหน้าเว็บเขียว
